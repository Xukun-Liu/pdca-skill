## 📖 使用说明（使用本模板前必读）

> **定位**：项目级 source of truth。任何接手的人（agent 启动 / 人类接手）读本文件即掌握"项目是什么、怎么做、做到哪、为什么这么做"。
> **派生关系**：任务级 spec 从本文件派生，头部填 `derived_from: spec_main_{项目名}.md §X`（X 用章节编号，不用行号）。
> **章节顺序**（最新全局置顶）：§1 状态 → §2 任务 → §3 目标 → §4 PRD → §5 技术栈 → §6 宪法 → §7 关键决策与治理（§7.1 ADR / §7.2 Sync Report / §7.3 风险登记 / §7.4 跨任务依赖）。
> **启动只读**：新对话启动只读 §1§2§3（最新状态+活跃任务+项目目标），§4-§7 按需读（指针跳转），控制 token 消耗。
> **维护**：§3§4§5 手工维护（改时才动）；§6 是混合段（不动）；§1§2§7 在 /act 阶段刷新指针目标（最新置顶）。复用 SUMMARY 三触发（启动检查/对话结束/交接时）。
> **章节类型**：纯指针（§1/§2/§7.1）/ 纯新内容（§3/§4/§5/§7.2/§7.3/§7.4）/ 混合型（§6）/ 固定段（文件头/使用说明/Self-Review/版本历史/占位符说明表）。
> **最新判定标准**【硬性】：按文件名时间戳 `YYYYMMDD_HHMM` 降序取第一个（不用 mtime，避免 touch/checkout 漂移）；TASK_STATE 文件无时间戳，按"当前活跃任务名"匹配 `TASK_STATE_{task_id}.md`。

> **状态说明**：✅ 已更新（下游已同步） / ⚠ 待更新（下游未同步，下次 /plan 处理）
> **大改规则**：整体重写（如方案 A 改方案 B）或 ≥3 文件 / ≥100 行 / 涉及核心模块的变更，按 spec_main 章节变更分别记多行，不合并。
