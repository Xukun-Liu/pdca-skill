### 9.1 测试要绿 vs 实现不许改冲突（REQ-027，characterization test）

> 当任务要求"测试必须全绿"但"实现代码不许改"时（典型场景：补测试类任务），冲突处理：
> - **锁当前行为**：用 characterization test（特征测试）锁住当前实现行为，即使当前有 bug 也先锁住
> - **标 KNOWN DEFECT**：在锁住的测试上标注 `# KNOWN DEFECT: {描述 bug}`，表明"我知道这里有问题，但本次任务不许修"
> - **交付条件**：测试全绿（characterization test 通过）+ 实现目录 git diff 为空（REQ-034a 防作弊点名禁止）
> - 详见 [references/plan/design/goal_brief.md](../references/plan/design/goal_brief.md) §3 防五种死法。

### 9.2 无 git 时 sha256 指纹（REQ-028，融合 v1.0.0）

> riji-skill /loop 模式强制要求 git 仓库（/loop 前置条件，非铁律6本身要求）。铁律6仅要求"已commit"（可用git/svn/手动备份）。极少数非 /loop 无 git 场景（如临时调研、一次性脚本），用 sha256 指纹核对文件完整性：
> - **指纹生成**：交付前对每个关键文件跑 `certutil -hashfile {文件} SHA256`（Windows）或 `shasum -a 256 {文件}`（macOS/Linux）
> - **指纹记录**：在 spec §9.2 表格记录文件名 + sha256 指纹
> - **交付核对**：交付时重新生成指纹，与记录对比，一字不差才算交付
>
> | 文件 | sha256 指纹 | 备注 |
> |------|------------|------|
> | {文件路径} | {64 位十六进制} | 关键文件 |
>
> ⚠️ 此机制仅限非 /loop 无 git 场景，/loop 模式强制要求 git（铁律6 + /loop 前置条件）。
