# 手绘呈现（hand-drawn-report）
> 阶段标签：D（旧标签，以头部 PDCA 标签为准）

> 版本：v1.0.0 | 更新：2026-07-13

把任意内容变成**手绘风视觉呈现**的能力：标题、要点、层级、对比、流程，整页用手绘速记 / 信息图风格画出来。替代原 `html-report-template.md`（HTML 双输出过重，已撤）。

---

## 一、触发场景

**默认伴随规则（核心）**：当用户说"汇报 / 总结 / 验收 / 交接 / 报告 / 梳理做了什么 / 盘点 / 能力清单 / 计划 / 方案 / 规划 / 规划一下 / 出方案 / 写spec / 写task / 写需求 / 做需求 / 需求分析 / 写设计 / 做设计"等**报告/计划/盘点类**词、或**AI 在对话内主动做总结/汇报/盘点/能力清单**时，**默认在对话内附一张手绘 SVG 速览图，并在会产出给用户看的 md 文档时也在该 md 文件顶部内联同款 SVG**——无论用户是否额外说"手绘"词。即：报告/计划/盘点/总结输出 = 对话内手绘 SVG + 文字叙述（+ md 顶部内联 SVG，若生成 md）；图默认带；仅当用户明确说"不要图 / 纯文本"才跳过。

当用户显式要手绘风视觉时读本文件：

- 触发词：`画成手绘图` / `手绘速记` / `涂鸦风` / `手账风` / `把这段可视化` / `来张信息图` / `用草图展示` / `手绘一下`
- 也覆盖"汇报 / 总结 / 验收 / 交接 / 报告 / 计划 / 方案 / 规划 / 盘点 / 能力清单 / spec / task / handoff"场景（这些触发词在 SKILL.md 钩子里已改指本文件）
- 🚀 **交接触发额外动作**（期3新增）：交接时除了生成手绘 SVG 速览图，还自动调用 `python scripts/handoff_tidy.py --task {任务名}` 做交接整理管线（守卫+归档+刷新+漂移+外部记忆清理+强制#3→#4同步+五问预跑+sync-matrix核对）

## 二、核心哲学：读信号，直接出，别先问

> 从内容和用户措辞推断模式 → 立即生成 → 让用户用自然语迭代修正。

- 绝不让用户先填表、先选风格/比例/布局
- 有歧义也先出"最可能的那个版本"，出完再补一句"想换可以说"
- 交互感应是：把内容交给一个"一看就懂、立刻画"的视觉思考者

---

## 三、Step 0 — 选输出路径

```
有图像生成工具（如 ImageGen / Gemini generate_image）？
├─ 是 → 图片路径：生成真实手绘 PNG + 可移植 prompt
└─ 否 → SVG 路径：生成手绘风 SVG（零依赖，见 §六）
```

用户可强制覆盖：

- 说"用 SVG" → 即使有图像工具也走 SVG 路径
- 说"只给我 prompt" → 只输出可移植 prompt，不出图

> 注：WorkBuddy 内建图像生成不叫 Gemini，默认走 **SVG 路径**，零 API key，最稳。

---

## 四、Step 1 — 读懂内容

- 一句话主旨是什么？
- 关系类型？（见下方 7 类）
- 真正要画的节点几个？超过 5–6 个就拆
- 内容很长（500+ 字）：拆成 2–3 张，不要硬塞一张

**关系类型 → 布局映射：**

| 关系类型 | 含义 | 默认布局 |
|----------|------|----------|
| `flow` | 步骤 / 流程 | 线性流程（B） |
| `concept` | 概念 / 中心主题 + 分支 | 中心辐射（A） |
| `comparison` | 两方对比 | 左右对比（C） |
| `story` | 时间线 / 叙事 | 竖版叙事（E） |
| `problem-solution` | 问题 → 方案 | 问题方案分栏（D） |
| `hierarchy` | 层级 / 分类树 | 中心辐射或分层堆叠 |
| `showcase` | 成果罗列 | 卡片网格 |

---

## 五、Step 2 — 静默判定模式（不弹菜单）

用"内容信号 + 用户措辞"默默决定：受众模式 / 视觉风格 / 比例 / 张数 / 布局。**打完状态行立即生成，不等确认。**

| 信号 | 模式 | 风格 | 比例 |
|------|------|------|------|
| 小红书 / 种草 / 情感叙事 | XHS Story | 暖色叙事手绘 | 3:4 |
| 论文 / 学术 / 导师 / 抽象概念 | Academic | 干净信息图（墨+一抹蓝） | 16:9 |
| 公众号 / 干货 / 教程 / tips | WeChat Knowledge | 知识卡片手绘 | 1:1 / 4:3 |
| 架构 / 流程 / 系统 / 技术过程 | Technical Whiteboard | 白板图 | 16:9 |
| 无明确信号 | General | 经典手绘速记 | 4:3 |

**歧义处理**：内容同时匹配两个模式 → 直接出最可能的，出完补一句：

```
（也可以做成 [另一模式] 风格，想切换说一声）
```

**关键信号追踪**：记下触发模式判定的 2–5 字证据短语，用于 Step 3 状态行，让用户一眼确认/纠正。

## 六、Step 3 — 状态行 + 立即生成

生成前先打状态行（让用户立即确认读法对不对）：

```
→ 读到：[关键信号] → [模式] · [风格] · [比例] · [N]张 · 生成中...
```

示例：

```
→ 读到：步骤流程+代码词汇 → 白板技术图 · 16:9 · 1张 · 生成中...
→ 读到：情感叙事+时间线 → 小红书叙事风 · 3:4 · 2张 · 生成中...
→ 读到：无明确信号 → 通用手绘 · 4:3 · 1张 · 生成中...
```

**2+ 张时**紧跟一行拆分计划（这是声明不是提问）：

```
→ 计划：图1 [覆盖…]，图2 [覆盖…]。生成中...
```

打完状态行立即生成，不等用户确认。

## 七、SVG 路径规范（无图像工具时）

核心标准：**看起来像人拿笔在纸上快画**，不像电脑生成的图。

1. **抖动路径**：用带轻微波动的 `<path>` 代替直 `<line>` / 完美 `<rect>`
   ```svg
   <!-- 抖动方框（非完美矩形） -->
   <path d="M50,50 C51,49 149,51 150,50 C151,50 151,149 150,150 C149,151 51,149 50,150 C49,150 49,51 50,50Z"
     stroke="#1a1a1a" stroke-width="2" fill="none" stroke-linejoin="round"/>
   ```
2. **笔触**：`stroke="#1a1a1a" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" fill="none"`；强调线 `stroke-width="3"`；辅助线 `stroke-width="1" stroke="#aaaaaa"`
3. **手写体**（中文）：`font-family="'Ma Shan Zheng','ZCOOL XiaoWei','Segoe Print',cursive"`；联网时 `<defs><style>@import url('https://fonts.googleapis.com/css2?family=Ma+Shan+Zheng&family=ZCOOL+XiaoWei&display=swap');</style></defs>`
4. **配色**（暖色，单图最多 2 个强调色）：墨 `#1a1a1a` / 底 `#fafaf7` / 强调黄 `#f5c842` / 砖红 `#e05a4e` / 蓝 `#4a90d9` / 浅奶 `#fef9e7`；Academic 只用墨+一抹蓝；XHS 用暖三元 `#f9a825`/`#e57373`/`#81c784`
5. **箭头**：弯曲杆 + 手绘箭头
6. **强调**：关键词下加抖动黄下划线

**布局模板（viewBox 起点）：**

- A 中心辐射（concept）：`0 0 700 500`，中心 `(350,250)`，分支距中心 180–200px
- B 线性流程（process）：`0 0 800 400`，方框 130×70，间距 40px，步骤号小圆圈
- C 左右对比：`0 0 700 500`，中线抖动分隔，左 3 项右 3 项
- D 问题→方案：`0 0 800 450`，左红 distress / 右蓝绿 calm
- E 竖版叙事：`0 0 450 700`，顶部 hook 标题 + 3–4 时刻 + 底部 takeaway

**手绘图标库（近似 path）**：灯泡 / 右箭头 / 勾 / 警告三角 / 齿轮（详见 installed skill 的 `references/svg-guide.md`）。

**质量检查**：有无完全笔直的线？字体是不是 Arial/sans？强调色超 2 个？太对称机械？文字溢出？标题是不是最强视觉元素（最大最粗）？

**诚实边界**：SVG 做不了照片级纹理 / 复杂人脸，遇到就在输出里说明"这是结构草图，建议用可移植 prompt 去真实图像工具出"。

## 八、Step 4 — 自然语迭代（永远有效）

| 用户说 | 动作 |
|--------|------|
| "更小红书" | 切 XHS Story，重出 |
| "更学术" | 切 Academic，重出 |
| "分成两张" | 重拆为 2 张，重出 |
| "竖版" | 切 3:4，重出 |
| "字少点" | 蒸馏到 ≤3 节点，重出 |
| "换 SVG" | 出 SVG 代替图片 |
| "只给我 prompt" | 只出 prompt |
| "重来" | 换变体重出 |
| "公众号风" / "技术图" | 切对应模式 |

绝不要求用户学模式名或参数 flag。

## 九、失败防护

- **禁止先问后出**——永远先推断、先出
- **内容溢出**——单图 ≤5–6 节点，多了拆
- **好看但读不懂**——视觉层级必须一眼清
- **长内容塞一张**——500+ 字规划多张
- **prompt 膨胀**——超 120 词说明没蒸馏够
- **图像工具挂了也要有输出**——永远回退 SVG

## 十、交付物

- **默认：生成的 md 文档顶部内联手绘 SVG 速览图**（内联、单文件自包含；符合"读 md 累、打开即看图"的诉求）。对话内不再强制带图；用户说"对话内也带图"才额外在对话内附一张。
- 用户说"存文件 / 保存 / 导出" → 额外存 `.svg` 单文件
- 始终附带**可移植 prompt**（供 Midjourney / FLUX / Ideogram 复用）
