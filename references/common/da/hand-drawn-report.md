# 报告速览图（hand-drawn-report）
> 阶段标签：D（旧标签，以头部 PDCA 标签为准）

> 版本：v1.2.0 | 更新：2026-08-31（v1.2.0 重大变更：**手绘风格退役**——用户反馈"丑且看起来复杂"，视觉层整体并入 [diagram-design.md](diagram-design.md) 编辑级设计系统；本文件只保留流程。文件名沿用历史，20+ 处引用不改名）

把任意内容变成**编辑级速览图**的能力：标题、要点、层级、对比、流程，用 diagram-design 设计系统画成干净的单图。替代原 `html-report-template.md`（HTML 双输出过重，已撤）与原手绘风视觉（v1.2.0 退役）。

> 🔴 **视觉规范不在本文件**：一切视觉（配色/字体/节点/连接线/图例/预算）以 [diagram-design.md](diagram-design.md) §5 设计系统 + §6 核心 SVG 原语 + §7 布局为唯一事实源。本文件只管"什么时候画、画哪种关系、怎么交付"。

---

## 一、触发场景

**默认伴随规则（核心）**：当用户说"汇报 / 总结 / 验收 / 交接 / 报告 / 梳理做了什么 / 盘点 / 能力清单 / 计划 / 方案 / 规划 / 规划一下 / 出方案 / 写spec / 写task / 写需求 / 做需求 / 需求分析 / 写设计 / 做设计"等**报告/计划/盘点类**词、或**AI 在对话内主动做总结/汇报/盘点/能力清单**时，**默认在对话内附一张编辑级速览图，并在会产出给用户看的 md 文档时也在该 md 文件顶部内联同款 SVG**——无需用户额外要图。即：报告/计划/盘点/总结输出 = 对话内速览图 + 文字叙述（+ md 顶部内联 SVG，若生成 md）；仅当用户明确说"不要图 / 纯文本"才跳过。

显式触发词：`把这段可视化` / `来张信息图` / `画个速览图`（也覆盖上述报告/计划/盘点场景）。

- 🚀 **交接触发额外动作**（期3新增）：交接时除了生成速览图，还自动调用 `python scripts/handoff_tidy.py --task {任务名}` 做交接整理管线（守卫+归档+刷新+漂移+外部记忆清理+强制#3→#4同步+五问预跑+sync-matrix核对）
- 🪦 **手绘风格已退役（v1.2.0）**：用户说"手绘/涂鸦风/手账风"时，不再出手绘风——直接出编辑级速览图并说明"手绘风已退役，这是编辑级版本"。上游 `diagram-design/references/primitive-sketchy.md` 保留作上游资产，不再路由。

### 双轨升级路径（v1.1.0 新增，v1.2.0 更新）

本文件 = **快速速览**轨道（报告伴随、秒出、md 内联 SVG）。遇到以下信号**改走专业图表轨道** [diagram-design.md](diagram-design.md)（39 种图型、自包含 HTML、可导出 PNG）：

- 用户点名专业图型：流程图 / 架构图 / 时序图 / 甘特图 / ER图 / 泳道图 / 桑基图 / 鱼骨图 / 看板图 / 类图 / 状态机图 / 部署图 / 依赖图 等
- 用户给了 `.drawio` / `.mmd` / 含 mermaid 块的 md 要重绘
- 用户要导出 PNG / SVG / 幻灯片尺寸

裸"画个图"无图型词无风格词 → 澄清菜单二选一（快速速览 / 专业图型）。**汇报/总结/验收/计划类报告场景的伴随速览图永远走本文件**，不因双轨改变。

## 二、核心哲学：读信号，直接出，别先问

> 从内容和用户措辞推断关系类型 → 立即生成 → 让用户用自然语迭代修正。

- 绝不让用户先填表、先选风格/比例/布局
- 有歧义也先出"最可能的那个版本"，出完再补一句"想换可以说"
- 交互感应是：把内容交给一个"一看就懂、立刻画"的视觉思考者
- **删除优先（来自 diagram-design）**：最高质量的改动通常是删除——目标密度 4/10，每个节点都要挣得自己的位置

---

## 三、Step 1 — 读懂内容

- 一句话主旨是什么？
- 关系类型？（见下方 7 类）
- 真正要画的节点几个？**超过 6 个就拆**（速览场景比专业轨的 9 节点上限更紧）
- 内容很长（500+ 字）：拆成 2–3 张，不要硬塞一张

**关系类型 → 图型映射（v1.2.0 起走 diagram-design 图型语法）：**

| 关系类型 | 含义 | 映射图型 | 画图前读 |
|----------|------|----------|----------|
| `flow` | 步骤 / 流程 | **流程图** | `diagram-design/references/type-flowchart.md` |
| `concept` | 概念 / 中心主题 + 分支 | **嵌套图**（包含层级）或**树图** | `diagram-design/references/type-nested.md` / `type-tree.md` |
| `comparison` | 多方对比 | 定量→**柱状图**；定位→**象限图**；**定性（方案A/B 优缺点等）→ 优先不画图走表格（§八 删减测试），确需图则拆成 showcase 卡片逐方一张** | `diagram-design/references/type-bar.md` / `type-quadrant.md` |
| `story` | 时间线 / 叙事 | **时间线图** | `diagram-design/references/type-timeline.md` |
| `problem-solution` | 问题 → 方案 | **流程图**（问题分支→方案分支） | `diagram-design/references/type-flowchart.md` |
| `hierarchy` | 层级 / 分类树 | **层级图**（layer stack）或**树图** | `diagram-design/references/type-layers.md` / `type-tree.md` |
| `showcase` | 成果罗列 | **SVG 卡片网格**：用 §6 Node box 模式仿卡片（白底+1px 描边+小圆点+标题/条目），2–3 列变宽排列 | 画法见 diagram-design.md §6 节点模式 + §8（§8 的 div 卡片仅限专业轨整页 HTML，速览内联 SVG 按 §6 仿制） |

> 映射表只定"用哪种布局语法"；具体画法（节点样式/连接线规则/图例条/预算）一律按所读 type-*.md + diagram-design.md §6/§7 执行，不在本文件重复。

## 四、Step 2 — 静默判定（不弹菜单）

用"内容信号 + 用户措辞"默默决定：关系类型 / 比例 / 张数。**打完状态行立即生成，不等确认。**

- **风格**：无风格可选——统一编辑级默认皮肤（diagram-design `references/style-guide.md` 默认令牌）。用户明确要品牌化/换肤时才走 diagram-design onboarding 流程
- **比例**：默认横版 `0 0 960 600`（doc-inline）；叙事/竖屏场景 `0 0 800 1000`
- **张数**：≤6 节点一张；超了按内容边界拆，拆分计划打进状态行

---

## 五、Step 3 — 状态行 + 立即生成

生成前先打状态行（让用户立即确认读法对不对）：

```
→ 读到：[关键信号] → [关系类型] · [图型] · [比例] · [N]张 · 生成中...
```

示例：

```
→ 读到：步骤流程+代码词汇 → flow · 流程图 · 960×600 · 1张 · 生成中...
→ 读到：阶段叙事+时间节点 → story · 时间线图 · 800×1000 · 2张 · 生成中...
→ 读到：无明确信号 → showcase · 卡片网格 · 960×600 · 1张 · 生成中...
```

打完状态行立即生成，不等用户确认。

## 六、视觉规范（薄指针，v1.2.0 重写）

**本文件不含视觉规范**。画 SVG 时遵循：

1. **设计系统**：[diagram-design.md](diagram-design.md) §5（语义色角色：paper `#f5f5f5` / ink `#2d3142` / muted `#4f5d75` / accent `#eb6c36`——accent 每图最多 1–2 处；hex 令牌全表见 `diagram-design/references/style-guide.md`）
2. **核心原语**：§6（不透明遮罩+样式方框的节点模式 / 先画箭头后画节点 / 正交圆角连接线 r=8 禁斜线 / 箭头标签必带遮罩且留 6–10px 间隙 / 图例=底部横条）
3. **布局纪律**：§7（4px 网格 / 专业轨预算 9 节点 12 箭头）+ **速览轨收紧预算（本文件自定）：≤6 节点 ≤8 箭头**，超限拆图
4. **无障碍**：`<svg role="img" aria-labelledby="...">` + `<title>` 是 svg 第一个子元素 + title/desc 带前缀 id（md 内联多图时防 id 撞车）
5. **字体**：Geist（节点名）/ Geist Mono（技术子标签）经 Google Fonts 引入；**离线降级为系统无衬线仍干净**（不再依赖手写字体）
6. **md 内联差异**：只内联 `<svg>` 本体（不带 HTML 外壳/页眉/卡片）；viewBox 按 §四 比例；复杂图要整页效果时改走专业轨出自包含 HTML

## 七、Step 4 — 自然语迭代（永远有效）

| 用户说 | 动作 |
|--------|------|
| "分成两张" | 重拆为 2 张，重出 |
| "竖版" | 切 800×1000，重出 |
| "字少点" | 蒸馏到 ≤3 节点，重出 |
| "换个图型" | 换 §三 映射的下一候选图型，重出 |
| "换配色 / 要品牌色" | 走 diagram-design style-guide 换肤，重出 |
| "重来" | 换布局变体重出 |
| "太挤 / 太复杂" | 删减测试（§八）砍节点重出，或拆两张 |

绝不要求用户学图型名或参数 flag。

## 八、失败防护

- **删减测试（v1.1.0 吸收自 diagram-design）**——出图前自问：能删的节点？能合并的节点（总是一起出现的两个节点=一个节点）？布局已表达的关系线？**最高质量的改动通常是删除**；三列表格能说清的事就不画图
- **禁止先问后出**——永远先推断、先出
- **内容溢出**——单图 ≤6 节点，多了拆
- **好看但读不懂**——视觉层级必须一眼清
- **长内容塞一张**——500+ 字规划多张
- **强调色泛滥**——accent 超 2 处 = 没有焦点，重选 1–2 个真正要用户先看的
- **手绘风回潮**——用户要手绘也出编辑级（§一 退役声明），别私自画抖动线
