# 报告生产流水线（取数 → 计算 → 成稿 → 校验 → 分发）

> 阶段标签：P · D（旧标签，以头部 PDCA 标签为准）

> 版本：v1.0.0 | 更新：2026-11-05
> 定位：把「手上一堆数据」变成「一份能发出去的报告」的**通用骨架**。只讲流程与门禁，不讲具体业务；选图、画图、写文档、汇报口吻各有专门模块（见 §四）。
> 来源：PDCA 自查+复核结构、`data_analysis.md` v2.0 防错体系（体检三问 / 对账四道 / 跑后三问）、`leader_report.md` 口径护栏三状态。

## 〇、先搞懂本质（决定怎么干）

报告生产不是"写文档"，是一条**流水线**：原料进、成品出，中间五道工序，每道工序有自己的次品判据。

| 工序 | 生活类比 | 一句话职责 | 出了问题会怎样 |
|------|----------|------------|----------------|
| **extract** 取数 | 采购 + 验货 | 把数据拿到本地，先看新不新鲜 | 源头错，后面全错且不报错 |
| **compute** 计算 | 加工 | 算出指标，并留一条可复算的路 | 数字错了，报告越漂亮越危险 |
| **build** 成稿 | 装配 | 结论先行，图/表/文各就各位 | 结论埋在第三页＝没写 |
| **verify** 校验 | 质检 | 用**机器可判**的方式检查成品 | 靠"再看一眼"＝没检 |
| **分发** 发货 | 发货 + 回单 | 决定发给谁、第一句说什么 | 附件对了，话没说对＝白做 |

> ⚠️ **核心命题**（来自 data_analysis v2.0）：数据分析最致命的缺陷是**算错的时候不报错**——错的数字和对的数字交付出去长得完全一样。所以本流水线的重心不在 build（好看），而在 **extract 的体检** 和 **verify 的断言**。

**为什么叫"四段式"**：extract → compute → build → verify 是四道**生产方式**；分发不改变产物，只决定"给谁、说哪句话"，所以单列为收尾一步。

```
raw 原始数据 ──extract──▶ work 清洗表 ──compute──▶ 指标表 ──build──▶ 报告文件
                          │                          │                   │
                          └────── 可重跑 ────────────┴──── verify ◀──────┘
                                                          │   （数字回查指标表）
                                                          ▼
                                                    分发 + 归档
```

**三条贯穿全程的纪律**
1. **原始数据只读**：`raw` 一律不改，所有清洗/计算写到新文件，保证随时能重跑。
2. **数字只有一个来源**：正文、图、表里的每个数字都必须来自「指标表」，不许在正文手打。
3. **跑后三问**：每跑完一步，回答"看到了什么 / 意味着什么 / 下一步查什么"；如果下一步和跑之前计划的一模一样，说明没真的在看输出。

## 一、四段式骨架（每段的职责 / 输入 / 产出 / 门禁）

### ① extract：取数 + 结构体检

| 项 | 内容 |
|----|------|
| **职责** | 把数据从文件/系统/接口取到本地，**先体检再计算** |
| **输入** | 源文件路径或接口、统计期间、口径说明（问用户，别自己拍） |
| **产出** | `raw` 原始副本（只读）+ 体检记录（行数、列名、主键唯一性、缺失率、异常值清单） |
| **门禁** | **体检三问全答**：①多少行、一行代表什么？②关键字段有无缺失/重复？③金额/数量合计是否落在合理量级？ |
| **常见翻车** | 直接 `pd.read_excel` 就开算，算到一半发现表尾有"合计行"被当成数据 |

> 细则见 [data_analysis.md](data_analysis.md) §2.4「结构体检三问」。

### ② compute：重算 + 对账

| 项 | 内容 |
|----|------|
| **职责** | 把指标逐个算出来，且**每条都能被另一条路复算** |
| **输入** | 清洗后的 `work` 表 + 口径定义 |
| **产出** | **指标表**（一行一个指标：名称 / 公式 / 值 / 口径 / 来源） |
| **门禁** | **对账四道**：表内合计＝明细合计｜外部基准能对上｜换一条路重算同值｜抽样回源核对 |
| **常见翻车** | 对不上时先写一句"口径差异"糊过去——**不一致先查原因，不解释** |

> 细则见 [data_analysis.md](data_analysis.md) §2.5「对账四道」。指标表建议直接落成 CSV，后续 verify 用它做数字回查。

### ③ build：成稿（图 + 表 + 文字）

| 项 | 内容 |
|----|------|
| **职责** | 把指标表变成「结论先行」的可读页面 |
| **输入** | 指标表 + 结论句清单（每条结论配 1 张图或 1 张表） |
| **产出** | 报告文件（md / html / docx / xlsx）+ 图 |
| **门禁** | 每个图上方有**结论句**；每张表有**口径脚注**；章节/图/表编号连续；首屏能看完全部结论 |
| **常见翻车** | 先画图后想结论，最后图很漂亮但回答不了任何问题 |

**分工（别在本模块里重造）**

| 要做什么 | 读哪个模块 |
|----------|-----------|
| 选什么图、matplotlib 怎么写 | [chart_cookbook.md](chart_cookbook.md)（关系驱动选型 + 6 个模板） |
| 把图落进 Excel / Word | [office_processing.md](../../do/code/office_processing.md) §二（Word 插图）/ §四（Excel 原生图表） |
| 汇报结构（六段式 / SCQA / 口径护栏） | [leader_report.md](../da/leader_report.md) §一 / §五 / §七 |
| 报告文件怎么命名、放哪个目录 | [document_specs.md](../pda/document_specs.md) |
| 流程图/架构图等结构图 | [diagram-design.md](../da/diagram-design.md)（数据图走 chart_cookbook，结构图走这里） |

### ④ verify：断言自检（机器可判，不是"再看一眼"）

| 项 | 内容 |
|----|------|
| **职责** | 用可执行的检查项给成品做质检，留下 pass/fail 证据 |
| **输入** | 产物文件 + 指标表 |
| **产出** | 自检记录（每条断言一行：检查项 / 结论 / 证据） |
| **门禁** | 下面 **6 类断言全绿**，任何一条红 → 不外发 |
| **常见翻车** | 只检查"文件能打开"，不检查"数字对不对" |

**六类断言（照抄可执行）**

| # | 断言 | 怎么查 | 红灯含义 |
|---|------|--------|----------|
| 1 | **数字回查** | 从报告正文正则抽数字，逐个在指标表里找同值（容差按量级定） | 有数字是手打的或算错 |
| 2 | **合计自洽** | 分项之和 = 总计（容差 0.01） | 口径不一致或漏项 |
| 3 | **期间一致** | 标题期间 = 文件名期间 = 数据实际期间（见 §二） | 沿用了上期配置 |
| 4 | **结构完整** | 章节数/图数/表数符合模板；图 1…图 N 连续无跳号 | 删改时漏了引用 |
| 5 | **无占位词** | 全文搜「待补」「待定」「XXX」「lorem ipsum」等 | 半成品被当成成品 |
| 6 | **可打开/零错误** | Office 文件能被库打开；Excel 扫 `#REF! #DIV/0! #VALUE! #N/A #NAME?` | 交付即打不开 |

```python
# verify 段最小可跑骨架：数字回查 + 合计自洽（纯标准库，内网可用）
import csv, re

met = {r["name"]: float(r["value"])
       for r in csv.DictReader(open("metrics.csv", encoding="utf-8"))}   # 列：name, value
text = open("report.md", encoding="utf-8").read()

# 1) 正文里每个「指标名 + 数字」都必须与指标表一致
for name, value in met.items():
    for m in re.finditer(re.escape(name) + r"[^\d\-]{0,12}(-?\d[\d,]*\.?\d*)", text):
        got = float(m.group(1).replace(",", ""))
        assert abs(got - value) < 1e-6, f"{name} 正文={got} 指标表={value}"

# 2) 分项合计 = 总计
parts = [v for k, v in met.items() if k.startswith("分项_")]
assert abs(sum(parts) - met["总计"]) < 0.01, "分项之和与总计不一致"
print("verify PASS")
```

### ⑤ 分发：一句话结论 + 口径

| 项 | 内容 |
|----|------|
| **职责** | 决定"发给谁、第一句话说什么、附什么" |
| **输入** | verify 通过的产物 |
| **产出** | 一条三段式交付消息 + 归档记录 |
| **门禁** | 口径**三态标注**（已知精确 / 估算 / 未知）；文件给**绝对路径**；按对象调详略（三级领导适配） |
| **常见翻车** | 甩一个路径不说结论；或结论里带一个没标口径的百分比 |

**交付消息固定三段**
1. **结论**：一句话说清"发生了什么、要不要动作"。
2. **关键数**：2–3 个能支撑结论的数字，每个后面跟口径（如"同比 +18%（对比 2025 年 10 月，含税确认收入）"）。
3. **文件**：绝对路径 + 一句话说明文件里有什么。

> 口径护栏细则见 [leader_report.md](../da/leader_report.md) §五；三级详略见同文件 §七。

## 二、期间配置单一来源（防"沿用上月＝假通过"）

**痛点**：报告期会同时出现在 **文件名、标题、SQL 过滤条件、图表 X 轴、正文** 五处。手工改必漏；漏了之后数字还是"自洽"的，所有断言都会通过——**这就是假通过**（跑了上月数据，却当成这月交付）。

**做法：一个 `period.json` 作为唯一来源，谁用谁读。**

```json
{
  "period": "2026-10",
  "label": "2026 年 10 月",
  "start": "2026-10-01",
  "end": "2026-10-31",
  "days": 31,
  "compare": "2025-10",
  "is_partial": false
}
```

```python
import json, datetime as dt

cfg = json.load(open("period.json", encoding="utf-8"))
start = dt.date.fromisoformat(cfg["start"])
end = dt.date.fromisoformat(cfg["end"])

assert start <= end, "期间起止颠倒"
assert (end - start).days + 1 == cfg["days"], f"天数不符：{(end - start).days + 1} vs {cfg['days']}"
year, month = cfg["period"].split("-")
assert year in cfg["label"] and str(int(month)) in cfg["label"], "标题期间与配置不一致"
print(f"报告期：{cfg['label']}（{cfg['days']} 天，对比 {cfg['compare']}）")   # ① 回显给人核对
```

**四条规矩**
1. **禁止硬编码期间**：所有期间文本/查询/文件名都从配置读；模板里出现 `2026-10` 字样就是隐患。
2. **第一步就回显**：生成报告的第一行输出打印配置，人眼 1 秒核对。
3. **未完整期要显式标**：`is_partial=true` 时标题必须写「（截至 10 月 20 日）」，且本月不下同比结论。
4. **换期自检一问**：把配置改回上月重跑，报告应该**明显变化**；如果几乎没变，说明某处硬编码了期间。

**没有脚本时的手工三项**：文件名期间＝标题期间｜过滤条件期间＝配置期间｜对比期有真实数据（别拿空表当"同比持平"）。

## 三、交付门禁（四道门，逐门放行）

| 门 | 判据 | 不通过怎么办 |
|----|------|--------------|
| **G1 数据门** | 体检三问全答 + 对账四道全过 | 回 extract / compute，**不许进 build** |
| **G2 内容门** | 每图有结论句、每表有口径脚注、结论在首屏 | 回 build |
| **G3 断言门** | 六类断言全绿 + Office 文件可打开 | 回 build / verify |
| **G4 分发门** | 口径三态已标注 + 绝对路径 + 期间一致 | 不外发 |

**打勾清单（可直接贴进 task.md）**

- [ ] 报告期配置已回显，与标题 / 文件名 / 数据实际期间一致
- [ ] 原始数据只读，清洗与计算可重跑
- [ ] 每个关键数字都能在指标表里查到同值
- [ ] 分项之和 = 总计
- [ ] 每张图上方有结论句，图题编号连续
- [ ] 口径三态已标注（精确 / 估算 / 未知）
- [ ] 全文无「待补 / 待定 / XXX / lorem ipsum」类占位词
- [ ] Office 文件能打开，Excel 零公式错误
- [ ] 交付消息含「一句话结论 + 关键数（带口径）+ 绝对路径」

> 与本文件配套的通用验收（DoD 四道质量闸门：规格自检 → diff 复查 → 测试证据 → 用户签收）见 [acceptance_criteria.md](../pc/acceptance_criteria.md)。本文件是**报告类任务的专项底线**，叠加在通用验收之上。
