## 〇、先搞懂本质（决定怎么干）

用一组生活类比记住数据分析在干嘛，能少走 80% 的弯路：

| 概念 | 本质类比 | 对操作的含义 |
|------|----------|--------------|
| **Excel 表格** | 一本**数字化账本 / 智能表格** | 行=一条记录，列=一个指标；能排序、筛选、算账 |
| **数据分析** | 从账本里**找出规律和答案** | 不是"把表做漂亮"，是"回答一个具体问题" |
| **数据清洗** | 下厨前**备菜**（洗、切、去烂叶） | 跳过这步，后面全错；真实工作 80% 时间花在这 |
| **数据质量评估** | 下厨前**先检查食材新不新鲜** | 先体检再决定修不修，别洗完才发现坏了 |
| **透视表** | 一台**自动分类汇总机** | 拖几下字段，几秒出"按地区×品类"的汇总 |
| **图表** | **用图讲故事** | 没人爱看数字墙，合适的图让结论一眼懂 |
| **函数公式** | 一个**不累的算账机器人** | 写一次，源数据一变自动重算（别手算硬塞） |

> ⚠️ 关键推论：分析前先想清楚"要回答什么问题"（见第一节），否则清洗、透视、画图都是白做。

## 一、分析前：先想清楚 4 个问题（Plan，最重要的一步）

类比：下厨前先想「吃啥 / 给谁吃 / 材料齐不齐 / 这顿是试菜还是宴席」，别一上来就开火。

| 要想清的问题 | 为什么 | 反面例子 |
|--------------|--------|----------|
| **① 要解决什么问题？** | 决定洗什么、算什么、画什么 | "帮我分析下这表" ❌（没目标）；"哪个地区利润最高" ✅ |
| **② 给谁看、要什么结论？** | 决定图的类型、详略、口径 | 给老板看要结论先行；给同事看要可复现步骤 |
| **③ 数据从哪来、够不够、可信吗？** | 垃圾进垃圾出，源头错全错 | 没确认口径就开始算，算出"负销售额" |
| **④ 这是探索还是推断？** | 两者证据强度完全不同，措辞必须不同（v2.0） | 在数据里翻到一个"渠道 C 周三转化特别高"的规律就当结论交付 ❌ |

> 一句话：**先把"问题"写成一句话验收标准**（配合 acceptance_criteria.md 的 Given/When/Then），再动手。这一步省 1 小时，后面省 1 天。

### 1.1 探索 vs 推断红线【硬性·v2.0】

> 来源：huashu-excel（Cassie Kozyrkov 的区分）。这是所有分析的前提。

| | 探索（analytics） | 推断（statistics） |
|---|---|---|
| 在做什么 | 看数据里**有什么** | 推断数据**之外**的东西 |
| 产出 | 好问题、假设、灵感 | 可对外声称的答案 |
| 卓越标准 | 速度 | 严谨 |
| 措辞 | 「数据里看到…这值得查一下」 | 「有证据表明…」 |

**红线：不能用同一份数据既生成假设又验证假设。** 在一份数据里切 20 个维度，总有一个看起来显著--违反这条的后果不是"不够严谨"，是**任何噪音都能被讲成规律**。探索发现要变成结论，需要新数据。

把探索发现写成推断结论，是最常见的数据欺诈，而且做的人通常没意识到自己在欺诈。

### 1.2 口径哲学【硬性·v2.0】

- **说不清口径的数字，不配叫结论。**「同比增长 37%」--分母是去年同期还是上个月？含不含退款？去没去重？声明口径不是出于谨慎，是让这个数字具备**被推翻的资格**。不能被检验的东西，连错的机会都没有。
- **能问就必须问，口径声明不是提问的替代品。** 用户在场时（对话式分析），先问「营收算净额还是毛额？退货挂回原单月份还是退货发生月？」再动手--问一句成本几十秒，替他拍板然后跑错方向的成本是几小时。口径声明（把替用户做的决定写出来交给他看）只在**确实没人可问**时使用（如批量自动化任务）。
- **口径随数字一起交付。** 每个关键数字后面注明口径，或在报告开头统一声明（详见 §十二）。

## 二、标准分析流程（脊柱式 7 步）

把网上公认的 `DATA -> CLEAN -> STRUCTURE -> ANALYZE -> VISUALIZE -> VERIFY -> REPORT` 工作流落成本地可照抄的步骤：

```
数据 分析脊柱
│
├─ 1. 取数+体检（DATA）  先体检再读入：结构三问 + 原始单元格检查（见 2.4）
├─ 2. 清洗（CLEAN）      去重 / 补缺失 / 统一格式 / 剔异常   ← 最费时
│   └─ ⚠️ 清洗前建议先做数据质量体检（见§七），避免洗完才发现数据不可用
├─ 3. 结构化（STRUCTURE）转"表格(Ctrl+T)"、做成一维表
├─ 4. 分析（ANALYZE）    透视表 + 核心函数 + 描述统计（陷阱自查见§八九十）
├─ 5. 可视化（VISUALIZE）按结论选图（见第五节）/ 组合看板（见§十一）
├─ 6. 验证+对账（VERIFY）对账四道：表内合计 / 外部基准 / 换路重算 / 抽样回源（见 2.5）
└─ 7. 出报告（REPORT）   结论先行 + 图表 + 数据可追溯（见§十二）
```

> 每条原则：原数据**留一份别动**（备份），所有改动在新表/新列做，方便回溯。

**跑后三问（贯穿全程的看输出纪律）【硬性·v2.0】**：每跑完一个脚本/一段代码，必须回答三个问题再往下走--**看到了什么、意味着什么、下一步查什么**。写死的判据：**如果跑完之后，你的下一步动作和跑之前计划的一模一样，说明你没有真的在看那个输出**。分析是一场不断分叉的调查；照固定顺序把步骤跑完，产出的只是几段输出。

**这次要走几步【v2.0】**：不是每个任务都要走满 7 步。判断标准只有一条：**这个数字会被别人拿去做决定吗？** 会，就必须走到第 6 步对账。查一个数、改个公式、干净表做透视，直接做，说清这个数怎么来的即可。拿不准就多走一步--少走一步的代价是数字错了没人发现，多走一步的代价只是慢一点。

### 2.1 意图→操作映射表（用户说一句话→该用哪个 pandas 操作）

> 来源：lark-base-data-analysis-sop。避免"先想清楚3个问题"后仍不知道该写什么代码。

| 用户说 | pandas 操作 | 示例 |
|--------|------------|------|
| "看几条/预览" | `df.head(N)` + `df[需要的列]` | `df[['姓名','部门']].head(10)` |
| "找某个人的信息" | `df.loc[df['id']==x]` | `df.loc[df['工号']=='A001']` |
| "按条件找" | `df.query()` 或 `df[df['列']>值]` | `df.query('销售额 > 10000')` |
| "排序/Top N" | `df.sort_values().head(N)` | `df.sort_values('销售额', ascending=False).head(10)` |
| "按 X 统计 Y" | `df.groupby('X')['Y'].agg()` | `df.groupby('部门')['销售额'].sum()` |
| "各 X 占比" | `groupby + transform` | `df['占比'] = df.groupby('X')['Y'].transform(lambda x: x/x.sum())` |
| "环比/同比" | `df.pct_change()` | `df['环比'] = df['销售额'].pct_change()` |
| "去重计数" | `df['列'].nunique()` | `df['客户ID'].nunique()` |
| "交叉表" | `pd.crosstab()` | `pd.crosstab(df['部门'], df['等级'])` |
| "查找匹配" | `df.merge()` | `df.merge(other, on='key', how='left')` |

### 2.2 数据源范围 3 步确认法

> 来源：lark-sheets + lark-base。分析前必须精确确认数据范围，否则透视/聚合结果全错。

| 步骤 | 做什么 | pandas 实现 |
|------|--------|-------------|
| ①确认表头与列对应 | 读表头 + 确认列名与列索引映射 | `print(df.columns.tolist())` + `print(df.dtypes)` |
| ②排除空行/汇总行/总计行 | 空行和汇总行会被当作数据参与聚合 | `df = df.dropna(how='all')` + `df = df[~df['关键列'].str.contains('合计\|总计', na=False)]` |
| ③读 3-5 行样本确认列义 | 表头语义含糊时（如"时间""日期"多列同名）需看实际值区分 | `print(df.head(5))` + `print(df.tail(5))` |

> 用 `df.shape` 确认数据边界（行数×列数），用 `df.dtypes` 确认字段类型（数字列不能是 object）。

### 2.3 全局 vs 局部原则

> 来源：lark-base Hard Rules。"最高/最低/最新/最早/Top/Bottom/总数/全部/异常/最大/最小"等全局语义，**必须用完整聚合或排序后取极值**，禁止用 `head()` 片面回答。

| 错误做法 | 正确做法 | 原因 |
|----------|----------|------|
| `df.head(5)` 回答"销售额最高的5个人" | `df.sort_values('销售额', ascending=False).head(5)` | head(5) 只看前5行，未必是全局最高 |
| 在筛选后子集上回答"总销售额" | 在完整数据上 `df['销售额'].sum()` | 子集求和 ≠ 全局总计 |
| 在局部数据上回答"平均" | `df['列'].mean()` 在完整数据上计算 | 局部均值不能代表全局 |

> 判断"数据是否完整"的信号：`df.shape[0]` 等于预期总行数、无未读取的分页数据。

### 2.4 结构体检三问（取数时先做，算任何业务数字之前）【硬性·v2.0】

> 来源：huashu-excel。**`pd.read_excel()` 读进来的那一刻，合并单元格、单元格格式、原始类型就全丢了，之后所有判断都建立在损毁的信息上。** 实测过一份典型的中国式销售表（标题占两行、两级表头、中间夹着「华东小计」、尾巴三行合计），用「找对表头+清千分位」这种看着挺周全的做法去算总额，**比真值高出 161%，且零报错、零警告**。

体检用 openpyxl 读原始单元格（能看见 pandas 看不见的东西：表头真实位置/多级表头/合并单元格/小计行/脚注行/隐藏行列/文本型数字/全角空格），然后回答三个问题--这三个问题对任何一张表都成立：

| # | 问题 | 为什么 | 判据 |
|---|------|--------|------|
| ① | **这张表的一行代表什么？** | 观测单位定错，后面每个百分比的分母都是错的 | 一笔交易？一个人？一个人一个月？说不出来就别开始聚合。顺带确认：这是明细还是已汇总的表？汇总表没法再下钻 |
| ② | **每一列的列名，是不是它字面的意思？** | 这是最贵的问题--**没有任何内部检查能发现它**（详见 §15.3 红线三） | 有数据字典读数据字典；没有就找发布方公开的一个总量对上去；对不上就停，别往下做 |
| ③ | **脚本说「没能自动解决」的值，是脏数据还是业务约定？** | 脏值往往不是错误而是你还不认识的业务语义 | 转不成数字的单号可能是退货单/坏账调整；逐个看一眼再决定，**丢掉的往往是信息而非噪音** |

贯穿判据：**脚本报告「已自动处理」的每一列，抽两个值回头看原始单元格。** 它报告成功，不等于它做对了（清洗脚本会把邮编 `01002` 转成 `1002.0` 然后报告成功，零警告）。

```python
# openpyxl 体检最小实现（先扫结构再谈数值）
from openpyxl import load_workbook
wb = load_workbook("data.xlsx", read_only=True)
ws = wb.active
for i, row in enumerate(ws.iter_rows(min_row=1, max_row=15, values_only=False), 1):
    for cell in row:
        if cell.value is not None and not isinstance(cell.value, (int, float, str)):
            print(f"R{i}C{cell.column}: 非常规类型 {type(cell.value)}")  # 日期对象等
    if i <= 10:
        print(f"R{i}: {[c.value for c in row[:8]]}")  # 肉眼看前 10 行结构
# 关注：合并单元格（ws.merged_cells.ranges）、小计行（某列含"合计/总计/小计"）、两级表头
```

### 2.5 对账四道（验证步的升级--我凭什么说这个数是对的）【硬性·v2.0】

> 来源：huashu-excel。原第 6 步只做"交叉核对/抽样核对"，v2.0 升级为四道对账。**闸门验的是「算得对」，不是「结论对」**--一份内部对账分毫不差、行数金额全部恒等的报告，可以整体错掉一个财年（只要那一列的列名不是它字面的意思）。内部一致性证明不了列语义。

| 道次 | 对什么 | 怎么做 | 不通过时 |
|------|--------|--------|----------|
| **① 表内合计** | 清洗后明细求和 vs 表内自带「合计/小计」行 | 表内合计是原表作者算出的**免费校验和**（几乎所有工具把它当噪音滤掉，那是真值）。`detail_sum` vs `claimed_sum` | 两种可能都得说出来：明细有错，或合计行有错（实测揪出过手填小计差 10 元） |
| **② 外部基准** | 关键总量 vs 发布方公开数字 | 找该数据源官方公布的一个总量对上去；顺带查「你的值 vs 行业中位数/头部/及格线」 | **内部全对≠整体对**。对不上就停（详见 §15.3 红线三） |
| **③ 换路重算** | 两条独立代码路径算同一结果 | 换个库/换种读法/重新实现同一套清洗规则；两条路对不上就是有一方错了 | 排查到一致为止 |
| **④ 抽样回源** | 随机抽 3-5 个数字回溯到源单元格 | 含空值行/异常格式行/首末行（对齐 §15.1 三方对照法） | 修完重跑 |

**没有合计行可对时**（原始系统导出/API 返回/数据库导出/问卷/日志--这一类数据永远不会有合计行）：默认走第③道换路重算；做不到的话，在交付物里**明写一句「本次结果没有独立校验来源」**，别让这句话混在提示里划过去。不要沉默地交付一个没验过的数。

## 三、数据清洗（最费时，80% 精力在这）

> ⚠️ 清洗前建议先做数据质量体检（见§七 数据质量评估），用5维度评分决定"值不值得洗、先洗哪里"。体检是"先验货"，清洗是"动手修"。

## 四、核心分析方法

### 4.1 描述统计（先看全貌--默认抗差统计）【v2.0 改写】

> 来源：huashu-excel（Tukey 抗差统计）。**业务数据几乎总是右偏**：销售额、客单价、停留时长，少数大客户/爆款就能把均值拉走。默认给**中位数 + 五数概括**，均值只当陪衬--均值大于中位数时，均值描述的不是任何一个真实个体。

```python
import pandas as pd
df = pd.read_excel("data.xlsx")
# 五数概括：min / P5 / P25 / 中位数 / P75 / P95 / max——默认给这个，不是默认给均值
print(df.describe(percentiles=[.05, .25, .5, .75, .95]))
print(df.median(numeric_only=True))   # 中位数（不受极端值影响）
```

**偏态判据三条【v2.0】**：

| 现象 | 怎么判断 | 正确动作 |
|------|----------|----------|
| **均值 > 中位数** | 明显右偏（少数大值拉高均值） | 用**中位数**描述「典型」，均值只作陪衬 |
| **均值落在两组之间** | 画直方图看是不是**双峰** | 先**分群**再各自描述，别用一个均值糊弄两个群体 |
| **有极值** | 极值可能是真实的大客户/爆款 | **不自动删**，先查为什么异常（见 §十） |

> 类比：体检报告——先看清"中位水平、最矮、最高、四分位"，再深挖异常。均值描述的不是任何一个真实个体。

### 4.2 透视表思维（分组汇总的核心）

四要素：**行 / 列 / 值 / 筛选**。把"按地区×品类算销售额"变成拖拽：
- 行=地区，列=品类，值=求和(销售额)，筛选=某时间段
- 可下钻（双击汇总格看明细）
- pandas 等价：`df.pivot_table(index="地区", columns="品类", values="销售额", aggfunc="sum")`

#### 4.2.1 透视表五级进阶（从拖拽到自动化）

| 级别 | 能力 | Excel 操作 | pandas 等价 | 什么时候用 |
|------|------|-----------|-------------|-----------|
| **L1 基础汇总** | 行×列×值三要素拖拽 | 插入→数据透视表→拖字段 | `df.pivot_table(index, columns, values, aggfunc)` | 第一次看数据全貌 |
| **L2 筛选联动** | 加筛选器+切片器实现交互 | 拖字段到"筛选"区→插入切片器→连接到所有透视表 | `df[df["地区"]=="华东"].pivot_table(...)` | 给别人看、需要交互筛选 |
| **L3 分组汇总** | 按日期/数值区间自动分组 | 右键日期列→组合→按月/季/年 | `df.groupby(pd.Grouper(key="日期", freq="M")).sum()` | 时间序列按月/季汇总 |
| **L4 计算字段** | 在透视表内新增自定义公式 | 透视表分析→字段/项目/集→计算字段 | `pivot["利润率"] = pivot["利润"] / pivot["收入"]` | 原始字段算不出、需要衍生指标 |
| **L5 多表关联透视** | Power Query 合并多表后透视 | 数据→获取数据→合并查询→透视 | `pd.merge(df1, df2, on="ID").pivot_table(...)` | 数据分散在多张表 |

> 类比：L1 是"算盘"（能算账），L2 是"遥控器"（能切换看），L3 是"自动分类"（按时间归档），L4 是"自定义公式"（算衍生指标），L5 是"多账本合并"（跨表汇总）。逐级递进，先掌握 L1-L2 解决 80% 场景。

#### 4.2.2 透视表常见模式决策表

| 你想分析什么 | 行 | 列 | 值 | 聚合方式 | 示例 |
|-------------|----|----|----|---------|------|
| 各地区销售额对比 | 地区 | — | 销售额 | 求和 | 华东 520 / 华南 380 |
| 地区×品类交叉表 | 地区 | 品类 | 销售额 | 求和 | 华东-A产品 200 / 华东-B产品 320 |
| 各产品占比 | 产品 | — | 销售额 | 求和+占比% | A产品 40% / B产品 60% |
| 月度趋势 | 月份(分组) | — | 销售额 | 求和 | 1月 100 / 2月 120 |
| 客户排名 | 客户 | — | 销售额 | 求和+降序 | 客户甲 500 / 客户乙 300 |
| 同环比对比 | 地区 | 月份 | 销售额 | 求和+差异% | 华东 1月 vs 12月 |
| 多指标看板 | 地区 | — | 收入/成本/利润 | 求和 | 华东 收入500/成本300/利润200 |

#### 4.2.3 pandas 透视进阶用法

```python
import pandas as pd

# 基础透视（等价 L1）
pivot = df.pivot_table(index="地区", columns="品类", values="销售额", aggfunc="sum")

# 多聚合函数（同时看求和+均值+计数）
pivot_multi = df.pivot_table(
    index="地区", columns="品类", values="销售额",
    aggfunc=["sum", "mean", "count"]
)

# 加小计/总计行
pivot_with_margin = df.pivot_table(
    index="地区", columns="品类", values="销售额",
    aggfunc="sum", margins=True, margins_name="总计"
)

# 按月分组透视（等价 L3）
df["日期"] = pd.to_datetime(df["日期"])
pivot_monthly = df.pivot_table(
    index=pd.Grouper(key="日期", freq="M"),
    columns="地区", values="销售额", aggfunc="sum"
)

# 计算衍生字段（等价 L4）
pivot = df.pivot_table(index="地区", values=["收入", "成本"], aggfunc="sum")
pivot["利润"] = pivot["收入"] - pivot["成本"]
pivot["利润率"] = (pivot["利润"] / pivot["收入"] * 100).round(1)

# 交叉表（计数专用，非数值聚合）
cross = pd.crosstab(df["地区"], df["状态"])
```

> ⚠️ pandas pivot_table vs Excel 透视表的关键差异：①pandas 不会自动生成"总计"行（需 `margins=True`）；②pandas 多层级索引（MultiIndex）读取时需 `pivot.loc["华东"]` 而非 `pivot["华东"]`；③导出到 Excel 前建议 `pivot.reset_index()` 拉平索引，否则行索引会变成不直观的多层表头。

### 4.3 核心函数（Excel 原生，够用 90% 场景）
| 函数 | 干什么 | 示例 |
|------|--------|------|
| `SUMIF` / `SUMIFS` | 按条件求和（单/多条件） | `=SUMIFS(销售额,地区,"华东",品类,"A")` |
| `COUNTIF` / `COUNTIFS` | 按条件计数 | `=COUNTIF(状态,"已完成")` |
| `AVERAGEIF` | 按条件平均 | `=AVERAGEIF(地区,"华北",利润)` |
| `VLOOKUP` / `XLOOKUP` | 跨表查值（XLOOKUP 更稳） | `=XLOOKUP(编号,表2!编号列,表2!名称列)` |
| `IF` | 条件分支 | `=IF(利润>0,"赚","亏")` |

> 公式铁律（来自 xlsx skill，违反必翻车）：**用公式别硬编码**；**公式必须重算**（openpyxl 写的是公式串不是值，交付前用 LibreOffice 重算）；**零公式错误**（扫 `#REF! #DIV/0!` 等）。详见 [office_processing.md](../../do/code/office_processing.md) 第四节。

### 4.4 相关性初探
- 两指标是否同涨同跌？画**散点图**肉眼看；或用 `df.corr()` 看相关系数（-1~1，越靠±1 越强）。

#### 4.4.1 相关分析三陷阱【v2.0】

> 来源：huashu-excel。

| 陷阱 | 说明 | 规避 |
|------|------|------|
| **Pearson 对离群值敏感** | 一个异常点能把相关系数从 0.1 拉到 0.8 | 用 `df.corr(method="spearman")` 秩相关，而非 Pearson |
| **相关不是因果** | 「用了优惠券的用户复购率高」——是券带来复购，还是本就要复购的人才领券？ | 观察数据分不出来，唯一办法是随机实验；无实验时措辞停在「相关」，不滑向「带来/提升/导致」 |
| **幸存者偏差** | 只统计还活着的样本，结论系统性偏乐观（"用了我们产品的公司平均增长 30%"——倒闭的不在数据里） | 分析留存/复购/成功率时先问：**哪些样本因为失败而从数据里消失了？** |

> 另见辛普森悖论：分组内都上升、合起来却下降，看总量必须同时看分组（见 §九 9.5）。

## 五、图表选型（用什么图说事）

> **第一步不是选图，是写结论句子【v2.0】**：把要传达的信息写成一句完整的话——「华东贡献六成销售额，但增速最慢」，不是「各地区销售额」。写不出这句话 = 还不知道要说什么，此时画任何图都是在装饰数据。这句话有两个用途：它决定图表类型，并且**它就是图表的标题**（探索阶段自己看的图除外，那时还不知道结论）。

选错图 = 故事讲歪。一张表记住：

| 你想表达什么 | 用这个图 | 反例 |
|--------------|----------|------|
| **趋势**（随时间变化） | 折线图 | 别用饼图 |
| **构成 / 占比** | 饼图 / 堆叠柱图 | 类别>5 用柱图别用饼 |
| **对比**（谁多谁少） | 柱形图 / 条形图 | 别用折线 |
| **分布**（集中哪） | 直方图 | — |
| **关系**（两变量相关） | 散点图 | — |
| **KPI 组合** | 组合图（柱+线） | — |

**去 chart junk（图表垃圾）**：别加多余阴影/立体/网格线；标题说清结论（"华东利润最高"而非"利润图"）；配色有主有次。

### 5.1 图表数据源精确控制

> 来源：lark-sheets-chart。图表引用透视表/汇总表时，数据源范围控制不当会导致图表完全失真。

| 原则 | 说明 | pandas 实现 |
|------|------|-------------|
| **排除总计行** | `pivot_table(margins=True)` 生成的 'All' 行必须排除，否则柱形图末尾多一根天文数字柱子、饼图多一个"总计"扇区 | `pivot.drop('All', axis=0).drop('All', axis=1)` |
| **合并标题行跳过** | 表格上方有合并大标题时，数据源范围从真正的列标题行开始 | `df.columns = df.iloc[0]; df = df[1:]` |
| **数据与表头分离** | 只画数据子集（如"只看某个分组"）时，不能把全局表头并进来 | `subset = df[df['分组']=='A'][['x','y']]` |
| **轴口径对齐** | 用户要"占比"时纵轴应是百分比，不能交付纵轴是原始计数的图 | `ax.set_ylabel('占比 (%)')` + 数据乘 100 |

### 5.2 扩展图表选型表

> 来源：lark-base-dashboard。在基础 6 种图表（折线/饼图/柱形/直方/散点/组合）外补充 3 种：

| 你想表达什么 | 用这个图 | 数据源配置 | matplotlib 实现 |
|--------------|----------|------------|-----------------|
| **流程转化**（各阶段递减） | 漏斗图 | 状态字段分组+数值聚合 | `plt.barh(range(n), values)` 倒序绘制 |
| **多维度评分**（产品对比） | 雷达图 | 多个维度字段+分类分组 | `polar=True` + `plt.plot(angles, values)` |
| **文本频率分布** | 词云 | 文本字段分组+计数 | `WordCloud().generate_from_frequencies()` |

```python
# 漏斗图示例
import matplotlib.pyplot as plt
stages = ['访问', '注册', '试用', '付费', '续费']
values = [10000, 6000, 3000, 800, 500]
plt.barh(range(len(stages))[::-1], values, color='steelblue')
plt.yticks(range(len(stages))[::-1], stages)
plt.xlabel('人数')
plt.title('销售漏斗：各阶段转化')

# 雷达图示例
import numpy as np
categories = ['性能', '价格', '服务', '易用性', '功能']
angles = np.linspace(0, 2*np.pi, len(categories), endpoint=False).tolist()
angles += angles[:1]
values_a = [4, 3, 5, 4, 3] + [4]  # 产品A
fig, ax = plt.subplots(subplot_kw=dict(polar=True))
```

### 5.3 图表感知精度阶梯（为什么别用饼图）【v2.0】

> 来源：huashu-excel（Cleveland & McGill 1984 图形感知实验）。人从不同视觉编码里读出数量的准确度有实测排序：

```
1. 位置（共同基线）        ← 最准
2. 位置（非对齐基线）
3. 长度、方向、角度
4. 面积
5. 体积、曲率
6. 明暗、色饱和度          ← 最不准
```

- **条形图用「长度 + 共同基线」编码，饼图用「角度和面积」编码**——同一份数据，读者从条形图读出的数字更接近真实。这是测量结果，不是审美偏好。
- 饼图唯一可用场景：**只有 2-3 个类别**，且只需传达「大概一半/大概三分之一」这类粗略印象；超过 3 类改用排序条形图。
- **加法的判据【v2.0】**：**不能进同一个 `sum()` 的数，也不该进同一组柱子。** 桶/人/美元/单量可以比大小；百分比、转化率、中位数不行（分母各不相同，画在一起=让读者比较两个不同的东西）。
- **永远不要用面积编码数量**（气泡大小、面积图宽度）——精度排第 4，且人普遍把面积差异读小（半径翻倍，面积是四倍，看起来只像两倍多）。

### 5.4 诚实性检查：一张图怎么在不撒谎的前提下误导人【v2.0】

> 来源：huashu-excel。每张图交付前过这 8 条。

| # | 检查项 | 规则 |
|---|--------|------|
| ① | **Y 轴基线** | 柱状图（条形图）必须从 0 起——柱子编码的是长度；折线图不必从 0（编码的是位置和斜率）。判据是**看用什么编码**，不是背"永远从 0" |
| ② | **双 Y 轴** | 两条不同量纲的线可凭空造出不存在相关性。替代：两张上下对齐小图，或都转成指数（基期=100）；非用不可时必须说明轴刻度是人为选的 |
| ③ | **时间窗口** | 起点/终点必须有业务理由（财年初/改版日/活动开始），不能"从这里开始看最好看" |
| ④ | **不完整的最后一期** | 本月只过了 12 天，最后一根柱必然矮一截。不完整期次去掉或虚线/浅色标注 |
| ⑤ | **颜色暗示因果** | 红=坏绿=好会绕过理性；「占比高」标红=下判断而非呈现事实。别用颜色深浅表"重要性" |
| ⑥ | **排序即观点** | 条形图按什么排序就在暗示什么；至少让读者知道排序规则 |
| ⑦ | **面积/图标缩放** | 同时缩放宽高，数值翻倍面积变四倍；只缩放一个维度或别用 |
| ⑧ | **只给导出量不给水平量** | 差值/增量/比率/指数都是导出量，丢掉了水平量信息。修法：导出量前补一张能读出水平量的图；版面只够一张时画水平量，导出量写进图题 |

> 补充：类别没有内在顺序时（地区/渠道/产品）一律按值排序；有内在顺序时（月份/年龄段）保持原顺序。色盲友好用蓝橙替代红绿。

## 六、简单预测（科普级，不堆公式）

| 方法 | 干什么 | 怎么做 |
|------|--------|--------|
| **移动平均** | 平滑波动看大势 | Excel：数据→数据分析→移动平均；pandas `df["值"].rolling(3).mean()` |

## 七、数据质量评估（先体检再决定修不修）

> 与第三章的关系：清洗是"动手修"，质量评估是"先体检"。建议在清洗前先跑一遍质量评估，用评分决定"值不值得洗、先洗哪里"。

类比：买菜回来先检查新不新鲜，别洗完切好才发现坏了。

### 7.1 质量五维度评分框架

| 维度 | 检测方法 | Excel 操作 / pandas 命令 | 评分标准（0-3 分） |
|------|----------|--------------------------|---------------------|
| **完整性** | 关键列空值率 | `=COUNTBLANK(A:A)/ROWS(A:A)`；`df.isnull().mean()` | 0=空值>20%；1=10-20%；2=5-10%；3=<5% |
| **准确性** | 抽样核对源系统 | 随机抽 30 行人工核对 | 0=错误率>10%；1=5-10%；2=1-5%；3=<1% |
| **一致性** | 同字段跨表比对 | `=VLOOKUP(...)` 比对；`df.merge(check=True)` | 0=不一致>15%；1=5-15%；2=1-5%；3=<1% |
| **时效性** | 最新记录日期 vs 今天 | `=MAX(日期列)`；`df["日期"].max()` | 0=>30天；1=15-30天；2=7-15天；3=<7天 |
| **唯一性** | 主键重复率 | `=COUNTIF(...)>1`；`df.duplicated().mean()` | 0=重复>5%；1=1-5%；2=0.1-1%；3=<0.1% |

### 7.2 质量评级

| 总分（满分15） | 评级 | 处置建议 |
|----------------|------|----------|
| ≥12 | 优质 | 直接进入清洗和分析 |
| 8-11 | 合格 | 先修低分维度再分析 |
| 4-7 | 需修 | 必须修复后才能分析，否则结论不可靠 |
| <4 | 不可用 | 退回数据源，重新采集 |

### 7.3 边界处理

| 场景 | 处理方式 |
|------|----------|
| **空表（0 行）** | 直接返回"数据为空，无法评估"，不进入后续流程 |
| **单行数据** | 跳过统计类维度（完整性/一致性无法计算），仅做业务规则检查 |
| **纯文本列（无数值）** | 完整性/唯一性可评估，准确性改为枚举值校验 |

## 八、趋势分析方法论（读懂过去和现在）

> 与第六章的关系：预测是"猜未来"，趋势分析是"读懂过去和现在"。先读懂趋势，再决定值不值得预测。

类比：看体温曲线——不是只看"现在37.5"，而是看"从36.5升上来的，还在升"。

### 8.1 趋势识别三件套

| 要素 | 含义 | 识别方法 | Excel 操作 / pandas 命令 |
|------|------|----------|--------------------------|
| **方向** | 上升 / 下降 / 平稳 | 连续3期对比 | `=IF(LAST3>PREV3,"↑","↓")`；`df["值"].diff().sign()` |
| **速度** | 变化率（快慢） | 平均环比变化率 | `=(本期-上期)/上期`；`df["值"].pct_change().mean()` |
| **拐点** | 加速 / 减速 / 反转 | 方向符号反转 | 连续3个时间周期方向变化（视数据粒度：月度用3个月，季度用3个季度） |

### 8.2 拐点识别方法

| 方法 | 怎么判断 | 适用场景 |
|------|----------|----------|
| **方向反转** | 连续3期上升后转下降（或反向） | 月度/季度业务数据 |
| **移动平均交叉** | 短期MA(3) 下穿/上穿 长期MA(12) | 波动较大的数据 |
| **同环比符号反转** | 同比正、环比转负（或反向） | 年度+月度双维度数据 |

### 8.3 趋势分解（概念级，不堆公式）

| 分量 | 含义 | 识别方法 |
|------|------|----------|
| **长期趋势** | 整体方向（去掉波动后的大势） | 移动平均（窗口≥6期）拟合线 |
| **季节波动** | 固定周期重复（如年底冲量） | 同月/同季的均值对比 |
| **随机扰动** | 无法解释的噪声 | 实际值 - 趋势值 - 季节值 |

> 加法模型：实际值 = 趋势 + 季节 + 随机；乘法模型：实际值 = 趋势 × 季节 × 随机。业务数据常选加法模型（简单够用）。

### 8.4 趋势外推注意事项

- 明确假设前提（线性可延续 / 季节模式不变）
- 附误差范围（历史拟合残差的标准差）
- 不可外推条件：拐点刚出现 / 外部环境剧变 / 数据点不足

### 8.5 边界处理

| 场景 | 处理方式 |
|------|----------|
| **数据点 < 4** | 无法识别拐点，仅报告方向（升/降/平） |
| **数据点 < 2** | 无法做趋势分析，仅报告当前值 |
| **时间粒度不一致** | 先统一到同一粒度（如都按月汇总）再分析 |

### 8.6 趋势陷阱库【v2.0】

> 来源：huashu-excel。"数字算对了但结论错了"的那一类问题，对账查不出来（对账只证明算得对，证明不了结论对）。

| 陷阱 | 现象 | 识别/规避 |
|------|------|-----------|
| **回归均值** | 上期最好的门店这期变差，未必是策略失效 | 若「上期最好的一批」和「上期最差的一批」这期都向中间移动，就是回归均值，不是干预起作用 |
| **周期性** | 日粒度数据几乎都有周内周期（周末高/低） | 看日环比全是星期几的噪音；用 7 日移动平均，或同比同一天（周一比周一） |
| **起点选择** | 从哪天开始画，能得出相反结论 | 起点必须有业务理由（财年初/改版日），不能"从这里开始最好看" |
| **不完整最后一期** | 本月只过了 12 天，最新点必然低，像断崖 | 不完整期次去掉或明确标注 |
| **缺失日期** | 缺失日期不报错，但让趋势线撒谎 | 先查断点：`pd.date_range` 全量比对找缺失天 |

## 九、结构拆解方法论（谁贡献、谁拖后腿）

> 与第四章的关系：第四章是基础统计（描述/透视/函数），本节是多维度拆解归因——把"总收入涨了10%"拆成"华东贡献+8%、华南贡献+5%、华北拖后腿-3%"。

类比：公司总业绩涨了，老板问"谁干的？"——拆到地区、产品、渠道才知道功劳怎么分。

### 9.1 拆解三步法

| 步骤 | 做什么 | 示例 |
|------|--------|------|
| **① 选维度** | 按什么切（地区/产品/渠道/客户） | 地区：华东/华南/华北/西部 |
| **② 选指标** | 拆什么数（收入/成本/利润/量） | 收入 |
| **③ 选方法** | 怎么算（占比 / 增量贡献 / 变化率归因） | 增量贡献 |

### 9.2 同比增量归因（归因分析）

> 把总量变化拆归因到各维度变化之和。

```
总量变化 = 各维度变化之和
示例：总收入变化 = 华东变化 + 华南变化 + 华北变化 + 西部变化
某维度贡献率 = 该维度变化 / 总量变化 × 100%
```

| 维度 | 本期收入 | 上期收入 | 增量 | 贡献率 | 判定 |
|------|----------|----------|------|--------|------|
| 华东 | 520 | 480 | +40 | 50% | 主力贡献 |
| 华南 | 380 | 340 | +40 | 50% | 主力贡献 |
| 华北 | 260 | 290 | -30 | -37.5% | 拖后腿 |
| 西部 | 120 | 110 | +10 | 12.5% | 小贡献 |
| **合计** | **1280** | **1220** | **+80** | **100%** | — |

> pandas 实现：`df.groupby("地区")["收入"].sum()` 对比两期，差值即增量。

### 9.3 结构变化识别

| 指标 | 干什么 | 怎么算 |
|------|--------|--------|
| **占比排名变动** | 谁的份额升了/降了 | 本期占比排名 vs 上期占比排名 |
| **集中度（CR3/CR5）** | 头部集中还是分散 | Top3/Top5 占总量的百分比 |
| **维度增减** | 有没有新增/消失的维度 | 本期维度集合 vs 上期维度集合做差集 |

### 9.4 拆解深度控制

- 最多 **3 层**（如：地区→产品→渠道），每层选 **Top5 + 其他**
- 超过3层容易"拆太碎看不出规律"
- 每层拆完写一句话结论（"华东主力是A产品，华南主力是B产品"）

### 9.5 归因与结构陷阱【v2.0】

> 来源：huashu-excel。

| 陷阱 | 说明 | 规避 |
|------|------|------|
| **辛普森悖论** | 分组内都上升，合起来却下降（例：UC Berkeley 整体女性录取率低，拆到院系女性反而更高） | 看总量必须同时看分组；不一致时分组结果通常才对 |
| **归因双模型** | 归因"正确答案"取决于模型（末次/首次/线性/时间衰减），同一份数据不同模型可得出完全相反排名 | 至少给两个模型的结果并说明差异；只给一个且不说模型=隐瞒最关键假设 |
| **漏斗时间窗** | 今天曝光的人可能明天才下单，用同一天数据算转化会系统性低估 | 按用户追踪（这批人 N 天内转化），不按天横切 |
| **cohort 不完整三角** | 最新批次只有 1 个月龄数据，右下角三角是空的不是 0 | 画热力图时把不完整格子留白，填 0 会画出假断崖 |

## 十、异常识别方法论（系统化找离群值）

> 与第三章的关系：清洗中的"异常值"条目是初步处理（条件格式高亮），本节是系统化方法（统计+业务规则+处置流程）。

类比：体检指标异常——不是看到红字就吃药，先分清"测量错误"还是"真有病"。

### 10.0 Twyman's Law 五问排查链【硬性·v2.0】

> 来源：huashu-excel。**Twyman's Law：任何看起来有趣或异常的数字，通常都是错的。** 这是整个数据分析领域最重要的单条定律。所以异常值的默认假设是「数据错了」，不是「发现了洞察」。逐个排查：

| # | 排查项 | 判据 |
|---|--------|------|
| ① | 单位错了吗 | 这一行是元，其他行是万元 |
| ② | 多打了一个零吗 | 数量级异常，和旁边行差一个量级 |
| ③ | 是汇总行/小计行混进来了吗 | 某行其实是「合计」却被当明细参与聚合 |
| ④ | 是测试数据吗 | 金额 1 分、名字叫「测试」「test」 |
| ⑤ | 以上都不是 | 才轮到「真实的业务异常，值得深挖」 |

> **脏值往往是业务线索而非噪音**：转不成数字的单号可能是退货单/坏账调整；「反常」的值常常编码着一条你还不认识的业务规则。**删之前必须知道它为什么异常**——黑天鹅、大客户、爆款都会表现为异常值，删掉它们等于删掉最重要的信息。特别漂亮的结论，先回去查数据（往往正因为它不该出现，才吸引人）。

### 10.1 异常分类

| 类型 | 含义 | 示例 |
|------|------|------|
| **点异常** | 单个值离群 | 某天销售额是平时的100倍 |
| **集体异常** | 一组值整体偏离 | 某地区所有产品销量同时暴跌 |
| **上下文异常** | 特定条件下不合理 | 夏天羽绒服销量暴增（季节错位） |

### 10.2 统计方法（数值列）

> ⚠️ **前置检查**：使用统计方法前，先画直方图判断数据分布形态。

| 方法 | 判定规则 | 适用前提 | 不适用时 |
|------|----------|----------|----------|
| **Z-score / 3σ 原则** | \|Z\|>3 为异常（Z=(x-μ)/σ，3σ 是 Z-score 的直观表述，二者等价） | 数据近似正态分布 | 偏态数据会误判，改用 IQR |
| **IQR（四分位距）** | 超出 Q1-1.5×IQR 或 Q3+1.5×IQR | 任意分布（对偏态较稳健） | 严重偏态时可先做对数变换再用 |
| **业务规则阈值** | 负销售额 / 超万倍均值 / 销量>库存 | 不依赖分布假设 | 小数据集首选 |

```python
# Z-score 法（近似正态分布时用）
import numpy as np
z_scores = np.abs((df["值"] - df["值"].mean()) / df["值"].std())
outliers = df[z_scores > 3]

# IQR 法（偏态数据优先用）
Q1, Q3 = df["值"].quantile([0.25, 0.75])
IQR = Q3 - Q1
outliers = df[(df["值"] < Q1 - 1.5*IQR) | (df["值"] > Q3 + 1.5*IQR)]
```

### 10.3 文本列异常识别

| 方法 | 干什么 | 怎么做 |
|------|--------|--------|
| **枚举值校验** | 值不在合法列表中 | `df[~df["地区"].isin(合法地区列表)]` |
| **频率异常** | 极罕见的值 | `df["产品名"].value_counts().tail(5)`（出现≤2次的） |
| **模式异常** | 格式不匹配 | 正则：`df[~df["手机号"].str.match(r"^1\d{10}$")]` |

### 10.4 异常处置四步

| 步骤 | 做什么 | 要点 |
|------|--------|------|
| **① 标记** | 标出异常行，不删除 | 新增列 `is_outlier = True/False` |
| **② 验证** | 是数据错误还是真实业务异常 | 查源系统 / 问业务方 / 看上下游 |
| **③ 处置** | 修正 / 保留 / 剔除 | ⚠️ **硬性约束**：剔除/修正只在新表新列做，原数据不动（与第三章备份要求一致）；剔除的行必须记录到单独的"已剔除记录"表，含剔除原因 |
| **④ 记录** | 留痕可回溯 | 记录：异常类型 / 验证结论 / 处置方式 / 处置人 / 时间 |

### 10.5 边界处理

| 场景 | 处理方式 |
|------|----------|
| **小数据集（<30 行）** | 统计方法不稳定（标准差/四分位数不可靠），改用业务规则阈值 |
| **空表 / 单行** | 无法计算统计量，跳过异常识别，仅做业务规则检查 |
| **全部相同的值** | 标准差=0，Z-score 无法计算，直接判定"无异常"（所有值一致） |

## 十一、可视化升级：看板与交互（多张图怎么组合）

> 与第五章的关系：图表选型是"单张图怎么选"，本节是"多张图怎么组合成看板"。内网环境用 Excel 原生功能实现，零外部依赖。

类比：单张图是"一张照片"，看板是"一整面照片墙"——有主有次、能联动筛选。

### 11.1 看板设计四原则

| 原则 | 含义 | Excel 实现方式 |
|------|------|----------------|
| **一屏一主题** | 一个看板只回答一个大问题 | 一个 Sheet 一个主题，Sheet 名即问题 |
| **信息分层** | KPI→趋势→明细，从上到下从简到繁 | 顶部 KPI 卡 → 中部图表 → 底部数据表 |
| **筛选联动** | 改一个筛选器，所有图表同步更新 | 插入→切片器→连接到所有数据透视表 |
| **适配打印** | A4 纵向/横向适配 | 页面布局→缩放比例→调整为1页宽 |

### 11.2 标准经营看板布局

```
┌─────────────────────────────────────────────┐
│  顶部：3-5 个 KPI 卡（大字+同比/环比）         │
│  [总收入 ¥1.28M ↑6.6%] [总订单 5200 ↑3%]     │
├──────────────────────┬──────────────────────┤
│  左：趋势折线图        │  右：占比饼图          │
│  （月度收入走势）      │  （地区收入占比）      │
├──────────────────────┴──────────────────────┤
│  底部：明细数据表（可筛选/排序）               │
└─────────────────────────────────────────────┘
```

### 11.3 图表组合模式

| 场景 | 组合 | 说明 |
|------|------|------|
| **经营月报** | KPI 卡 + 趋势折线 + 占比饼图 + 明细表 | 最常用，4 张图够用 |
| **产品分析** | 柱形图对比 + 散点图相关性 + 堆叠柱图结构 | 3 张图 |
| **异常监控** | 折线图（标异常点） + 条件格式表格 | 2 张图 |

### 11.4 配色规范

| 角色 | 色数 | 建议 |
|------|------|------|
| 主色 | 1 个 | 蓝/绿（数据类首选冷色） |
| 辅色 | 2 个 | 与主色同色系深浅 |
| 警示色 | 1 个 | 红/橙（仅用于异常/负值） |
| 总计 | ≤4 色 | 禁用彩虹色/渐变色 |

> ⚠️ 图表数量建议：单个看板 ≤5 张图，超过5张考虑拆成多个看板。

### 11.5 KPI 卡片设计规范（来自 data-processing 插件）

> KPI 卡片是看板顶部的"核心数字区"——一眼看到最重要的 3-5 个指标。设计不当会喧宾夺主。

| 设计要素 | 规范 | 反例（禁止） |
|----------|------|-------------|
| **结构** | 一行文字标签 + 一个格式化数值，够了 | 加装饰图标/emoji/花边分割线 |
| **语义色** | 左侧 3px 色条体现状态（绿=正常/红=异常/橙=关注） | 整卡片变色/大面积彩色背景 |
| **变化值** | 有时间对比时加一行小字变化值（↑6.6% / ↓3.2%） | 彩色箭头图标/大号↑↓符号 |
| **数值格式** | 千分位+单位（¥1.28M / 5,200件） | 裸数字 1280000 / 无单位 |
| **高亮数量** | 3-5 个 KPI 卡，选最重要的 | 堆 10+ 个 KPI 卡变成数字墙 |
| **排列** | 横向等宽排列，间距一致 | 大小不一/随意排列 |

**openpyxl 实现 KPI 卡片色条**：
```python
from openpyxl.styles import PatternFill, Font, Alignment, Border, Side

def kpi_card(ws, row, col, label, value, status="normal"):
    """在指定位置画一个 KPI 卡片（标签+值+左侧色条）"""
    color_map = {"normal": "00A651", "warning": "FF8C00", "danger": "FF0000"}
    bar_color = color_map.get(status, "00A651")
    # 左侧 3px 色条（用窄列填充模拟）
    ws.cell(row, col).fill = PatternFill("solid", fgColor=bar_color)
    ws.column_dimensions[ws.cell(row, col).column_letter].width = 0.5
    # 标签
    ws.cell(row, col+1, label).font = Font(size=10, color="6B7280")
    # 数值
    ws.cell(row+1, col+1, value).font = Font(size=18, bold=True, color="1F2937")
```

## 十二、报告合成方法论（结论怎么写）

> 与第十五章的关系：交付验收是"检查清单"（逐项打勾），本节是"报告结构模板"（怎么组织语言和图表）。

类比：做完实验写报告——不是把数据堆上去就行，得有结论、有证据、有建议。

### 12.0 洞察三层 + 基线层【v2.0】

> 来源：huashu-excel。**数据报告最常见的失败，不是分析不够深，而是把描述当成了洞察。** 能改变某人某个决定的东西才叫洞察；改变不了任何决定的，无论多准确都只是描述。

| 层次 | 例 | 读者反应 |
|------|-----|----------|
| **描述 What** | 华东销售额 6497 万，占比 44% | 「哦。」 |
| **诊断 Why** | 华东占比高因门店密度大，但单店产出低于华南 | 「有点意思。」 |
| **含义 So what** | 华东是存量盘不是增长盘，新增预算应投华南 | 「那我得改预算。」 |

**每条洞察出手前过三问**：①它能改变什么决定？答不上来就删或往下挖一层 ②若结论是反的，读者会做不同的事吗？不会则这个维度不重要 ③有没有可能是数据错了（Twyman's Law）——特别漂亮的结论先回去查数据。

**基线层（结论后、论点前的坐标系）【v2.0】**：报告开头紧接结论，先给一段"基线"——让读者知道"盘子有多大、有哪些玩家、谁最大"。没有这一层，读者不知道你在跟什么比、离正常多远。基线图选型：若干主体一个时点→排序条形图（标绝对值+占比）；若干主体随时间→绝对堆叠（不是百分比堆叠，百分比会把总量拍平）。**基线图必须把玩家列全**——「其他」超过两成说明分类没做完或数据覆盖不全，回头查数据，不是画出来了事。

### 12.1 报告四段结构

| 段落 | 内容 | 篇幅建议 | 图文配比 |
|------|------|----------|----------|
| **① 结论先行** | 1 句话结论 + 3 个支撑数字 | 3-5 行 | 纯文字 |
| **② 趋势概述** | 方向 + 速度 + 拐点（见§八） | 1-2 段 | 图文并茂（1张趋势图） |
| **③ 结构拆解** | 谁贡献 / 谁拖后腿（见§九） | 1-2 段 | 表格为主（1张拆解表） |
| **④ 异常说明** | 发现了什么 + 怎么处置（见§十） | 1 段 | 图表+文字（1张异常图） |

### 12.2 报告分级

| 级别 | 篇幅 | 阅读时间 | 适用场景 |
|------|------|----------|----------|
| **摘要版** | 1 页 | 5 分钟 | 给老板看，只要结论和建议 |
| **详版** | 3-5 页 | 15 分钟 | 给团队看，含分析过程和图表 |
| **附录** | 不限 | 按需 | 数据明细 + 方法论说明 + 代码 |

### 12.3 数字呈现三原则

| 原则 | 含义 | 正例 vs 反例 |
|------|------|-------------|
| **附口径** | 数字怎么算的 | "收入（含税）" ✅ vs "收入" ❌ |
| **附时间范围** | 哪个时段的 | "2026年Q2（4-6月）" ✅ vs "近期" ❌ |
| **附对比基准** | 跟什么比 | "同比+6.6%（vs 2025年Q2）" ✅ vs "涨了" ❌ |

### 12.4 措辞标准：证据强度决定语气【v2.0】

> 来源：huashu-excel。证据有多强，措辞才能多肯定。

| 你有的证据 | 能说 | 不能说 |
|-----------|------|--------|
| 单期观察 | 「这段时间里 A 高于 B」 | 「A 比 B 好」 |
| 多期一致 | 「A 持续高于 B」 | 「A 导致了…」 |
| 有对照实验 | 「A 带来了 X% 提升」 | 「A 一定会…」 |
| 相关分析 | 「X 与 Y 同向变动」 | 「X 提升了 Y」 |

- **样本 < 30 时，任何百分比都要同时给绝对数**（"增长 200%"基数是 2，说的是四个人的事）。
- **不确定就把不确定写进句子里**，别用确定句+括号免责（「大概率是渠道 C 的问题，但我只有两周数据，换个窗口可能不成立」>「渠道 C 是主要问题（注：样本有限）」）。

### 12.5 报告自检清单

- [ ] 结论回答了第一节写的"那句话问题"
- [ ] 每个数字附口径 + 时间范围 + 对比基准
- [ ] 趋势段有方向 + 速度 + 拐点
- [ ] 拆解段有增量归因表
- [ ] 异常段有处置记录
- [ ] 预测附假设 + 误差范围

## 十三、数据合并与转换（多表怎么拼）

> 与第四章 4.3 节的关系：4.3 讲 VLOOKUP/XLOOKUP 单函数用法，本节聚焦"多表合并的模式选择 + 合并后的校验逻辑"。

类比：拼积木——先看接口对不对（关联键），拼完再检查有没有掉件（行数校验）。

### 13.1 多表合并三模式

| 模式 | 场景 | pandas | Excel 原生 |
|------|------|--------|------------|
| **纵向堆叠** | 同结构表行数增加（1月+2月→Q1） | `pd.concat([df1, df2])` | 复制粘贴 / Power Query 追加查询 |
| **横向关联** | 不同表列数增加（订单表+客户表） | `pd.merge(df1, df2, on="客户ID")` | VLOOKUP/XLOOKUP（见4.3节）/ Power Query 合并查询 |
| **主从汇总** | 主表带汇总值（客户表+订单汇总） | `df1.merge(df2.groupby("ID").sum(), on="ID")` | SUMIFS（见4.3节） |

### 13.2 宽长表转换

| 转换方向 | 什么时候用 | pandas | Excel |
|----------|----------|--------|-------|
| **宽→长** | 画图需要（部分 Python 绑图库要求长格式） | `df.melt(id_vars=["地区"], var_name="月份", value_name="值")` | Power Query 逆透视列 |
| **长→宽** | 透视表需要（人看宽表更直观） | `df.pivot(index="地区", columns="月份", values="值")` | 数据透视表 |

### 13.3 关联键校验（合并前必做）

| 检查项 | 为什么 | 怎么查 |
|--------|--------|--------|
| **键唯一性** | 一对多会导致行数膨胀 | `df["键"].duplicated().sum()`，>0 说明一对多 |
| **键类型一致** | 文本"1" ≠ 数字1 | `df1["键"].dtype == df2["键"].dtype` |
| **空键处理** | 空键关联后变 NaN | `df.dropna(subset=["键"])` 先删空 |

### 13.4 合并后校验

| 校验项 | 怎么验 | 预期 |
|--------|--------|------|
| **行数变化** | `len(merged) vs len(df1)` | 纵向=行数相加；横向=主表行数（一对一）或增加（一对多） |
| **关联键命中率** | `merged["键"].notna().mean()` | ≥95% 为合格；<95% 检查键不匹配原因 |
| **非匹配行处置** | `merged[merged["键"].isna()]` | 保留（标记NaN）/ 剔除（记录原因）/ 补全（查源系统） |

### 13.5 边界处理

| 场景 | 处理方式 |
|------|----------|
| **空表合并** | 直接返回另一张表，记录"其中一张表为空" |
| **单行数据** | 正常合并，但统计校验无意义 |
| **键全不匹配** | 停下检查——是键错了还是两张表确实无关 |

### 15.1 公式等价性验证：三方对照法

> 来源：lark-sheets-formula-translation。公式翻译/计算完成后，挑 3-5 个代表性输入行验证三方一致。

**代表性输入行选择策略**：首行 / 中段行 / 末行 / 含空值行 / 含异常格式行 各选一。

| 对照方 | 值来源 | 一致性要求 |
|--------|--------|------------|
| ① Excel 原公式语义 | openpyxl 回读 `cell.value` | 公式文本正确 |
| ② Python 独立复现 | pandas 手算等价值 | 计算逻辑等价 |
| ③ openpyxl 回读值 | 保存后重新打开读取 | 值未丢失/未变形 |

> 三方全部一致才交付。仅靠语法转换通过不足以保证业务结果正确——数组/日期差/范围引用上极易出现等价性偏差。

### 15.2 交付验收 6 项追溯清单

> 来源：lark-base-data-analysis-sop。形成交付输出前必须确认 6 项：

| # | 追溯项 | 确认内容 |
|---|--------|----------|
| 1 | 问题范围 | 是局部样例、单点定位、全局原始记录、聚合分析、多表关联还是查询后写入 |
| 2 | 筛选层面 | 筛选/排序/聚合是否在正确的层面完成（不是在局部数据上做全局结论） |
| 3 | 局部数据可靠性 | 如果用了局部数据，输入是否在可靠范围内（超过阈值应改用全量聚合） |
| 4 | 数据完整性 | `df.shape` 覆盖全部数据行；无遗漏的空行/汇总行被当作数据 |
| 5 | 关联回查 | 如果涉及关系查询，是否按业务 key 精确回查，交付输出来自关联表真实字段 |
| 6 | 来源链路 | 交付输出能追溯到：表→字段→筛选条件→排序/聚合条件→连接键 |

> 任一项无法确认时，继续查询或明确说明只能得到局部结论。

> 这些是 DoD 的「分析专项底线」，叠加 acceptance_criteria.md 的 4 道质量闸门（规格自检→diff 复查→测试证据→你签收）与 office_processing.md 的 Excel 铁律，构成完整验收闭环。

### 15.3 七条红线（踩的时候看起来一切正常）【硬性·v2.0】

> 来源：huashu-excel。它们有个共同点：踩的时候，一切正常。

| # | 红线 | 含义 |
|---|------|------|
| 一 | **退出码 0 = 算得对，≠ 结论对** | 绿灯只说明没算错，不说明没问错；两者距离大到能装下一个错误的财年 |
| 二 | **脚本说「成功」≠ 做对了** | 清洗脚本会把邮编 `01002` 转成 `1002.0` 还报成功零警告；凡「自动处理好」的列抽两个值回看原始单元格 |
| 三 | **内部全对得上，证明不了列读对了** | 行数/总和守恒在「把 A 列当 B 列」时全部通过。两个变体更阴：①加总=100% 不代表覆盖了以为的范围（「份额」悄悄变成「这两家之间的相对比例」）②派生列（「评委直觉分」=五维均分取整，`corr(x, round(x))`=0.944 是算术常数）——一列是不是另一列算出来的得动手验，不能靠列名 |
| 四 | **样本量够 ≠ 统计上站得住** | 「每组超 60 人」挡不住不显著；分组下结论前看区间跨不跨 0 |
| 五 | **别用自己选的窗口证自己想要的结论** | 换一个窗口再算，结论还在才算数 |
| 六 | **口径不一样的数不能进同一个 sum()** | 多币种混加、毛额净额混着加；加之前问一句：这列每个数的分母都一样吗？ |
| 七 | **不要自己审自己** | 自查时带着「它应该成立」的先验；这就是独立质控（§15.4）存在的全部理由 |

### 15.4 独立质控七问（另派一个没参与创作的 agent）【硬性·v2.0】

> 来源：huashu-excel。质控不可选，且不能由你自己做——给它的指令是**从原始数据重算**，不是核对交付物和中间产物对不对得上（抄写错误最易发现也最不值钱，真正的错都在上游）。

| 查什么 | 问法 |
|--------|------|
| **窗口** | 这个时间段是不是挑出来的？换一个窗口，结论还在吗？ |
| **粒度** | 聚合得够不够细？有没有把混合效应算成了主效应？ |
| **基准** | 外部基准的分母、年份、地域，和你的数对得上吗？ |
| **声称** | 「已剔除某某偏差」这类话，代码里真做到了吗？ |
| **派生** | 参与关键结论的列，有没有哪一列其实是另一列算出来的？ |
| **重叠** | 各条结论涉及的人群/金额画个韦恩图，是不是同一批？（实测：两条并列建议各自成立，合起来在救同一笔钱） |
| **缺席** | 结论依赖的维度，数据集里到底有没有？补上它会不会让结论翻面？（实测：一份预算「少了 5.68 亿」全口径过六闸门，换市本级是 +18.75 亿方向相反——数据集里根本没有「资金来源」这一维） |

> **复核顺序建议**：先查证据等级最高的几条结论和首屏 KPI，把作者自曝的「最脆弱三条」放最后——自曝清单只列得出他意识到的疑虑，真正危险的地方恰恰是他没意识到自己做了选择的地方。跑不了子任务的环境，退一步把交付物和原始数据一起交给用户独立复核。

## 十六、颜色编码体系速查表（金融模型标准）

> 来源：xlsx skill Color Coding Standards。做涉及财务/预算/预测的 Excel 时，颜色不是装饰，是"语义"——让人一眼分清哪些是手填的、哪些是算出来的。

### 16.1 文字颜色编码

| 颜色 | RGB | 含义 | 什么时候用 | openpyxl 代码 |
|------|-----|------|----------|--------------|
| **蓝色** | 0,0,255 | 手填输入值 / 场景假设数字 | 用户手动输入的原始数据、需要调整的参数 | `Font(color="0000FF")` |
| **黑色** | 0,0,0 | 公式和计算结果 | 所有 `=` 开头的公式单元格 | `Font(color="000000")` |
| **绿色** | 0,128,0 | 同簿跨表引用 | 公式引用了同一工作簿其他 Sheet 的单元格 | `Font(color="008000")` |
| **红色** | 255,0,0 | 跨文件外部链接 | 公式引用了其他 Excel 文件的数据 | `Font(color="FF0000")` |

> 类比：蓝字=你亲手写的答案，黑字=计算器算的，绿字=从隔壁房间拿的，红字=从别的楼拿的。颜色越"远"，数据来源越"远"。

### 16.2 背景色编码

| 颜色 | RGB | 含义 | 什么时候用 | openpyxl 代码 |
|------|-----|------|----------|--------------|
| **黄色底** | 255,255,0 | 需关注的假设 | 关键假设单元格、需要用户更新的参数 | `PatternFill("solid", fgColor="FFFF00")` |
| **浅蓝底** | 234,242,255 | KPI 高亮 | 核心指标、汇总行、当前期关键值 | `PatternFill("solid", fgColor="EAF2FF")` |
| **白色底** | 255,255,255 | 斑马纹奇数行 | 数据区域隔行底色（第1/3/5...行） | `PatternFill("solid", fgColor="FFFFFF")` |
| **浅灰底** | 247,249,252 | 斑马纹偶数行 | 数据区域隔行底色（第2/4/6...行） | `PatternFill("solid", fgColor="F7F9FC")` |

### 16.3 数字格式速查

| 数据类型 | 格式代码 | 示例 | openpyxl 代码 |
|----------|----------|------|--------------|
| **年份** | 文本（不千分位） | 2024（不是 2,024） | `cell.number_format = "@"` |
| **货币** | `$#,##0` | $1,280 | `cell.number_format = "$#,##0"` |
| **零值显示为横杠** | `$#,##0;($#,##0);-` | $1,280 / ($500) / - | `cell.number_format = "$#,##0;($#,##0);-"` |
| **百分比** | `0.0%` | 12.5% | `cell.number_format = "0.0%"` |
| **估值倍数** | `0.0x` | 8.5x | `cell.number_format = '0.0"x"'` |
| **负数** | 括号 `(123)` | ($123) 不是 -123 | `cell.number_format = "#,##0;(#,##0)"` |

### 16.4 颜色编码使用原则

| 原则 | 说明 |
|------|------|
| **语义色仅用于告警** | 红/橙/黄不用于装饰，只标识异常/需关注 |
| **整表颜色≤5种** | 不含灰阶（白/浅灰/边框灰不算） |
| **装饰移除后信息仍完整** | 去掉所有颜色后数据应仍可读 |
| **假设值必须黄底标记** | 任何需要用户修改的参数必须标黄底 |
| **公式禁止硬编码** | 蓝字输入值用单元格引用，不写死在公式里 |

## 十七、可视化设计原则（反"AI 生成味"）

> 来源：data-processing 插件 §可视化原则。产出图表和看板应像内部分析工具（Grafana/Metabase 风格），不像 AI 生成的演示页面。追求**数据密度高、视觉干扰低**。

### 17.1 禁止清单（典型 AI 生成特征）

| 禁止项 | 为什么禁 | Excel 中的体现 |
|--------|---------|---------------|
| 装饰性渐变背景/发光效果 | 干扰数据阅读 | 不用渐变填充/艺术字 |
| 花哨入场动画 | 无实际价值 | Excel 图表不加动画 |
| 在 CSS 中罗列大段配色板 | 噪声大 | 配色≤4色（见§十一.4） |
| 厚重圆角+大阴影卡片 | 浪费空间 | 表格用 1px 细线边框 |
| 装饰性图标/emoji/花边 | 无信息量 | 图表标题不加 emoji |
| 为"好看"加的空状态卡片 | 无数据支撑 | 不加无数据的装饰行 |

### 17.2 遵循清单

| 原则 | 含义 | Excel 实现 |
|------|------|-----------|
| **安静的容器** | 面板用 1px 细线边框或极浅底色区分 | 边框色 `#D9DEE7`，不用厚框 |
| **数据说话** | 图表直接标注关键值，不依赖动效 | 数据标签直接标在图上 |
| **克制的颜色** | 默认配色即可，语义色仅用于告警 | 蓝为主色，红仅标异常 |
| **稳定的布局** | 面板尺寸固定，不因数据变化抖动 | 列宽行高固定 |
| **功能性优先** | 筛选/排序因为有用才加 | 切片器/筛选器有实际需求才加 |

### 17.3 图表设计规范

| 要素 | 规范 | 禁止 |
|------|------|------|
| **配色** | 使用 Excel 默认主题配色 | 自定义彩虹色板 |
| **网格线** | 保持默认浅灰 | 加粗/变色网格线 |
| **图例** | 单系列不加图例 | 单系列也加图例 |
| **标题** | 标题即结论（"华东利润最高"） | 标题只写"利润图" |
| **数据标签** | 关键值直接标注 | 标注所有点导致拥挤 |

### 17.4 可视化自检清单

交付图表/看板前逐项检查：

- [ ] 去掉所有装饰性颜色后，信息是否仍然完整可读？
- [ ] 整体是否像 Grafana/Metabase 的输出？而不是 Dribbble 概念稿？
- [ ] 颜色数量是否 ≤ 5 种（不含灰阶）？
- [ ] 单系列图表是否有多余的图例？
- [ ] 标题是否说清了结论而非只写图名？
- [ ] 有没有为"好看"而加的无信息量元素？

## 十八、专业表格格式规范

> 来源：xlsx skill Visual Table Design + Number Formatting + Reusable Styling Helpers。做表不是把数据塞进去就行，格式规范决定了别人能不能快速读懂。

### 18.1 表格视觉设计三要素

| 要素 | 规范 | openpyxl 实现 |
|------|------|--------------|
| **斑马纹** | 数据区域隔行底色（不含表头/合计行），低对比度交替 | 白色 `#FFFFFF` + 浅灰 `#F7F9FC` |
| **边框** | 细线浅色边框，外框+行分隔优先，不用满格粗框 | 边框色 `#D9DEE7` |
| **层级强调** | 小计/合计行用粗体+顶部边框强调，不用粗框圈每格 | `Font(bold=True)` + 顶部 medium 边框 |

### 18.2 KPI 视觉层次

| 场景 | 处理方式 |
|------|----------|
| 汇总行 / 合计行 | 粗体 + 顶部边框强调 |
| 当前期关键值 | 浅蓝底 `#EAF2FF` + 粗体 |
| 异常值 / 负值 | 红色字或红色底 |
| 核心指标标签 | 在指标旁加短标签（"核心 KPI"/"异常"） |

### 18.4 公式构造规则

| 规则 | 正例 | 反例 |
|------|------|------|
| **假设值独立单元格** | `=B5*(1+$B$6)` | `=B5*1.05`（1.05 写死） |
| **用单元格引用不用硬编码** | `=SUM(B2:B9)` | `=5000`（Python 算完塞数字） |
| **除零防护** | `=IF(B6=0,"",B5/B6)` | `=B5/B6`（B6=0 时 #DIV/0!） |
| **跨表引用用正确格式** | `=Sheet2!A1` | `=A1`（忘了 Sheet2） |
| **硬编码值加注释** | 旁边写"来源: XX报表, 2026-07" | 无来源说明 |

### 18.5 美化任务 5 维度全覆盖 checklist

> 来源：lark-sheets-visual-standards。用户说"美化/整理/让表更清晰"时，必须遍历 5 个维度逐一落地，只动一处就交付属于违规。

| 维度 | 规范 | 验收点 |
|------|------|--------|
| ①表头格式 | 加粗+背景色+居中 | 表头与数据行有视觉区分 |

### 18.6 列宽自适应像素估算

> 来源：lark-sheets-visual-standards。禁止硬编码固定列宽，须根据列实际内容长度估算。

| 内容类型 | 每字像素 | padding | 上下限 |
|----------|----------|---------|--------|
| 中文 | 15-18px | +10-16px | 80~400px |
| 英文/数字 | 7-9px | +10-16px | 80~400px |

```python
def estimate_column_width(ws, col_letter, min_width=8, max_width=50):
    """根据列实际内容估算 openpyxl 列宽（中文字符按 2 个宽度计算）"""
    max_len = 0
    for cell in ws[col_letter]:
        if cell.value is None:
            continue
        text = str(cell.value)
        visual_len = sum(2 if ord(c) > 127 else 1 for c in text)
        max_len = max(max_len, visual_len)
    width = min(max(max_len + 2, min_width), max_width)
    ws.column_dimensions[col_letter].width = width

# 用法：遍历所有列自适应
# for col in "ABCDEFGH":
#     estimate_column_width(ws, col)
```

### 18.7 格式刷三步分层法

> 来源：lark-sheets-visual-standards。基于模板区域批量格式化时，分三步执行避免混乱。

| 步骤 | 做什么 | openpyxl 实现 |
|------|--------|--------------|
| **Step1 格式铺开** | 将模板行的全部格式（样式、边框、数字格式）复制到目标区域，只铺格式不动值/公式 | `copy.copy(cell.font)` / `copy.copy(cell.fill)` / `copy.copy(cell.border)` |
| **Step2 内容覆写** | 将实际数据写入，不传任何样式（格式已在 Step1 就位） | `ws.cell(r, c).value = data` |
| **Step3 微调收尾** | 调整行高列宽、处理合并单元格、扩展条件格式范围 | `ws.row_dimensions[r].height = ...` |

```python
import copy

def clone_style_from_template(ws, template_row, target_rows, min_col, max_col):
    """将模板行格式复制到目标行（只复制格式，不动值）"""
    for r in target_rows:
        for c in range(min_col, max_col + 1):
            src = ws.cell(template_row, c)
            dst = ws.cell(r, c)
            dst.font = copy.copy(src.font)
            dst.fill = copy.copy(src.fill)
            dst.border = copy.copy(src.border)
            dst.alignment = copy.copy(src.alignment)
            dst.number_format = src.number_format
```

## 二十、条件格式设计方法论

> 来源：lark-sheets-conditional-format。条件格式不是"改颜色"，是"让颜色随数据自动变化"——数据一改，颜色跟着改，不用手工重涂。

### 20.1 触发词→规则类型映射

用户说以下词汇时，必须用条件格式而非静态背景色：

| 触发词 | 条件格式规则类型 | openpyxl 实现 |
|--------|-----------------|--------------|
| "标红/标黄/上色/染色" | CellIsRule（单元格值判断） | `CellIsRule(operator='lessThan', formula=['0'], fill=red_fill)` |
| "高亮/突出/标记" | CellIsRule 或 FormulaRule | `FormulaRule(formula=['$A1>阈值'], fill=highlight_fill)` |
| "颜色随数据变" | ColorScaleRule（色阶） | `ColorScaleRule(start_type='min', start_color='FF0000', end_type='max', end_color='00FF00')` |
| "数据条/进度条" | DataBarRule | `DataBarRule(start_type='min', end_type='max', color='638EC6')` |
| "前 N 名标绿" | FormulaRule + RANK | `FormulaRule(formula=['RANK($A1,$A$1:$A$30)<=3'], fill=green_fill)` |

### 20.2 四大陷阱防范

| 陷阱 | 错误写法 | 正确写法 | 原因 |
|------|----------|----------|------|
| **空值比较** | `=E1<=TODAY()` | `=AND(E1<>"",E1<=TODAY())` | 空值被当作 0，全表标红 |
| **背景 vs 前景色混淆** | "标红"→用 `font.color`（红字） | "标红"→用 `fill`（红底）；"文字红"才用 `font.color` | 中文"标红/高亮/染色"指背景色 |
| **辅助列绕过** | 用 expression 一步搞定多条件 | 先建判断列，再做条件格式引用判断列 | 用户明确要求辅助列时禁止绕过 |
| **未读样本就写规则** | 只读表头就写条件格式 | 先读 3-5 行数据样本确认列对应 | 列顺序可能与预期不同 |

### 20.3 openpyxl 条件格式代码模板

```python
from openpyxl.formatting.rule import CellIsRule, FormulaRule, ColorScaleRule, DataBarRule
from openpyxl.styles import PatternFill

# 1. 负值标红（背景色）
red_fill = PatternFill("solid", fgColor="FFC7CE")
ws.conditional_formatting.add('B2:B30',
    CellIsRule(operator='lessThan', formula=['0'], fill=red_fill))

# 2. 过期日期标黄（防空值陷阱）
yellow_fill = PatternFill("solid", fgColor="FFEB9C")
ws.conditional_formatting.add('E2:E30',
    FormulaRule(formula=['AND(E2<>"",E2<=TODAY())'], fill=yellow_fill))

# 3. 色阶（低→高 红→黄→绿）
ws.conditional_formatting.add('F2:F30',
    ColorScaleRule(start_type='min', start_color='FF0000',
                   mid_type='percentile', mid_value=50, mid_color='FFEB84',
                   end_type='max', end_color='63BE7B'))

# 4. 数据条
ws.conditional_formatting.add('G2:G30',
    DataBarRule(start_type='min', end_type='max', color='638EC6'))

# 5. Top 3 标绿
green_fill = PatternFill("solid", fgColor="C6EFCE")
ws.conditional_formatting.add('H2:H30',
    FormulaRule(formula=['RANK(H2,$H$2:$H$30)<=3'], fill=green_fill))
```

> 类比：条件格式像"自动感应灯"——有人（数据）来了灯亮，走了灯灭。手动涂色像"手电筒"，涂了就不会自动变。
