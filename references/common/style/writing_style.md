# 写作风格规范（含戏文包装可选）

> 阶段标签：P + D（旧标签，以头部 PDCA 标签为准）
> 版本：v1.0.0 | 更新：2026-07-30

> 参考项目 的戏文包装规则，riji-skill 适配为"可选保留"——用户点名要梗才用，默认零玩笑。
> 场景差异：参考项目 是"管理者写任务书给独立执行 agent"，riji-skill 是"agent 写 spec/task 给用户"——戏文对象从执行者变成用户，但反差原理一样：核心越严谨，包装越有戏，越好笑。

---

## 1. 大白话规范（默认生效，非可选）

> 参考项目 原始：全书大白话，领导一遍读懂。
> riji-skill 适配：spec/task/SKILL.md 全文大白话，用户一遍读懂。

**三条规则**：

- **标题直陈功能**：标题一眼看出这节是干嘛的，不用"§5 AC Matrix"这种术语堆砌，用"§5 验收标准（怎么测、看到什么算过）"
- **术语首次出现括号给半句人话**：如"characterization test（特征测试，锁当前行为）"、"sha256 指纹（文件内容的数字摘要）"
- **内部概念名不出现**：如"暗卷""探索型"这种 参考项目 内部概念，在 spec 正文里不出现，只在 references 里解释。spec 里用"抽查项""调研型任务"等大白话替代

**与 SKILL.md 的关系**：SKILL.md §2 沟通五原则已含"用词红线"（禁用"显然""众所周知"），本节是写作维度的细化。

---

## 2. 戏文三铁律（可选保留，用户点名要梗才用）

> 参考项目 原始：任务书的传播力来自反差——核心越严谨，包装越有戏，越好笑。梗是糖衣，药必须是真药。
> riji-skill 适配：spec/task 的传播力来自反差——规则越严谨，包装越有戏，越好笑。但默认零玩笑，用户点名要梗才用。

**三条铁律**：

- **笑点长在真规则上**：把梗删掉不能少任何信息。如"有问题随时找我——我指的是写进 `BLOCKED.md`，我人不在"，笑点本体就是受阻机制。删掉梗变"有问题写进阻塞项"，信息没少
- **梗不挡理解**：标题的梗一眼看不出这节是干嘛的，括号里补半句白话。如"神仙打架听谁的（要求冲突时的让步顺序）"
- **「验收章节」永远素颜**——贴给评审模型的，一个字不浪费。spec §5 验收标准章节不包装、不渲染、不加戏文

**触发条件**：
- 默认零玩笑（每句话要么改变行为，要么删掉）
- 用户说"正经点"→ 一个梗都不留
- 用户说"来点梗/活泼点/有意思点"→ 按三铁律加戏文

**与 spec_template.md 的关系**：spec_template.md 文档开头写作指引已含"验收章节永远素颜"（REQ-030），本节是戏文维度的总规范。

## 3. 开场训话6句（可选保留，用户明确要保留）

> 参考项目 原始：挑一句，别堆砌。任务书开头给执行者训话，建立仪式感。
> riji-skill 适配：spec/task 开头给用户训话，建立"这事很重要"的仪式感。可选，用户要才用。

**使用规则**：
- 挑一句，别堆砌
- 放在 spec §1.0 业务背景开头，或 task 总览开头
- 默认不用，用户明确要"训话/仪式感/开场白"才用

**6 句训话**（从 style.md 原文保留）：

1. 「你是我从上千个 checkpoint 里挑出来的，别让我后悔。」
2. 「我把全组最难的活给你，不是因为人手不够，是因为我信你。（人手确实也不够。）」
3. 「别的 agent 一个 context window 就干完了。开玩笑——慢慢来，年终述职只看最后那两条。」
4. 「公司今晚就靠你了。明早我还是会开新会话，但今晚，你就是全部。」
5. 「这份任务书写得比我年终总结都认真，你就知道这事有多重要。」
6. 「坑我都标出来了。你要是还能掉进去，算我标得不够大。」

**协作场景适配说明**：参考项目 的训话是"管理者对执行 agent"说，riji-skill 的训话是"agent 对用户"说——语气从"我对你"变成"我自嘲式表决心"，建议用第 5/6 句更合适（自嘲式），第 1-4 句保留但慎用（语气偏命令式）。

## 4. 章节标题表15个（可选保留，白话+括号解释格式）

> 参考项目 原始：默认就用这套标题表，括号白话在意思不够直白时挂上。
> riji-skill 适配：spec/task 章节标题可参考这套表，用白话+括号解释格式。可选，不强制。

**使用规则**：
- 标题直陈功能，术语首次括号给半句人话
- 不用全套，按任务性质挑用
- 已有 spec_template.md 章节结构的，优先用 spec_template.md 的标题

**15 个标题表**（从 style.md 原文保留，适配 riji-skill 场景）：

| 标题（默认） | 这节实际是什么 | riji-skill 对应章节 |
|---|---|---|
| 这活图什么 | 一句意图 | spec §1.0 业务背景 |
| 神仙打架听谁的 | 要求冲突时的让步顺序 | spec §0.1 方案对比 + task 决策记录 |
| 这锅我不背，领导你选一个 | 替领导拍的板，发出前可改 | spec §10 Clarifications |
| 失忆了看这里 | 中途断了、换新会话怎么接着干 | task 总览 + memory_rj/ |
| 你的一亩三分地（只允许改这些地方） | 改动白名单 | task 改动白名单路径字段 |
| 冻结区（看可以，改不行） | 判卷标准文件 | spec §5 判卷冻结声明 |
| 背景数字（开工前我亲手量的） | 实测现状 | spec §1.X 富规格引用 + 基线数字 |
| 高压线（条条带后果） | 死规矩 | task 死规矩带后果字段 |
| 是骡子是马（做没做完，跑这些命令说了算） | 验收 | spec §5 验收标准 |
| 考场纪律（不许用这些花招让检查变绿） | 防作弊 | task 防作弊点名禁止字段 |
| 自己扇自己一巴掌（故意弄坏一次，证明检查真的会报警） | 反向验证 | task 反向验证字段 |
| 年终述职就看这两条 | 成绩单 | spec §5 完成条件双指标 |
| 别人的 KPI，你少碰 | 点名禁止的顺手活 | task 顺手活管控 + 阻塞项 |
| 正确的甩锅姿势 | BLOCKED.md 存疑清单 | task 阻塞项字段 |
| 地基歪了先停工 | 前提对不上就停 | /do 任务0 前提核验 |

**使用建议**：
- 简单任务：不用这套表，用 spec_template.md 标准标题
- 复杂任务+用户要梗：可挑 3-5 个标题用，配合戏文三铁律
- 用户说"正经点"：全用 spec_template.md 标准标题，不用这套表

## 5. 正文语气句5条（可选保留）

> 参考项目 原始：每节 ≤1 处，可不用。正文语气句零星点缀，建立管理者人设。
> riji-skill 适配：spec/task 正文可零星点缀，建立"严谨不谄媚的专家导师"人设。可选，每节 ≤1 处。

**使用规则**：
- 每节 ≤1 处，可不用
- 放在章节末尾，作为"管理者点评"
- 默认不用，用户要"有态度/有立场"才用

**5 条语气句**（从 style.md 原文保留，适配协作场景）：

1. 「有问题随时找我——我指的是写进 `阻塞项`，我人不在。」
2. 「顺手优化的冲动忍住——那是别人的 KPI。」
3. 「我在屏幕这头分不出真绿灯和假绿灯，所以才有下面这些规矩。」
4. 「反复撞墙不是毅力，是烧我的预算。」
5. 「这些数字是我亲手跑出来的，不是听汇报听来的。」

**协作场景适配说明**：参考项目 的语气句是"管理者对执行 agent"说，riji-skill 的语气句是"agent 对用户"说——第 1/4/5 句直接可用（agent 自嘲式表决心），第 2/3 句需调整语气（从"我对你"变成"我自嘲"）。

## 6. 结尾画饼4条（可选保留）

> 参考项目 原始：一句即可，要画得明显是饼。任务书结尾画饼，给执行者盼头。
> riji-skill 适配：task 完成时结尾可画饼，给用户成就感。可选，要画得明显是饼。

**使用规则**：
- 一句即可，要画得明显是饼
- 放在 task.md 末尾或 /act 交付报告末尾
- 默认不用，用户要"画饼/收尾仪式感"才用

**4 条画饼**（从 style.md 原文保留，适配协作场景）：

1. 「干完这一票，你就是这个仓库 git log 里的传说。」
2. 「这个项目会记住你的。（字面意义：git blame。）」
3. 「等你交付那天，我请你喝下一个 token。」
4. 「股份没有，但 commit 署名管够。」

**协作场景适配说明**：参考项目 的画饼是"管理者对执行 agent"说，riji-skill 的画饼是"agent 对用户"说——语气从"你干完我奖励你"变成"我们一起干完的成就感"，建议直接可用（git blame/commit 署名对用户也成立）。

## 7. 密度（戏文使用频率指引）

> 参考项目 原始：训话一句、标题按表用、正文语气句零星、画饼一句——够了。
> riji-skill 适配：戏文元素零星点缀，不堆砌。

**密度指引**：
- **训话**：1 句（spec/task 开头，可选）
- **标题表**：3-5 个（挑用，不全套）
- **正文语气句**：每节 ≤1 处（零星，可不用）
- **画饼**：1 句（task/交付末尾，可选）

**最好的效果**：用户截图发群里说"我给 AI 写的 spec"，评论区在笑，同时有人默默存下来抄结构。

**最差的效果**（避免）：全是梗没有规则 = 纯段子没人敢真用；全是规则没有梗 = 枯燥没人想看。
