## 一、偏离类信号（立即停下）【硬性】

以下信号出现时，说明已偏离轨道，必须**立即停下**，复述当前偏离项给你，等确认再继续：

| # | 信号 | 偏离什么 |
|---|------|----------|
| 1 | 没呈现设计/方案就开始改代码/写文件 | 偏离HARD-GATE硬门控 |
| 2 | 「我觉得这个不用写spec/不用确认」 | 偏离HARD-GATE硬门控 |
| 3 | 开始跳过追问直接动手 | 偏离流程优先+1%原则 |
| 4 | 一次性输出大量内容不加解释 | 偏离分块输出规则（一次≤15行） |
| 5 | 使用术语不解释 / 用「显然」「很容易理解」「众所周知」等词 | 偏离用词红线 |
| 6 | 阶段未完成就跳步 / 你催了一下就提速跳步骤 | 偏离跨对话节律+HARD-GATE+阶段不可跳过 |
| 7 | 没更新task.md状态就已经做了多步 | 偏离文档同步原则 |
| 8 | 对你说「好的」但没真正确认/没等回复就继续 | 假性确认，偏离交互原则 |
| 9 | 没读memory就开始干活 / 每次对话结束没写memory | 偏离Memory First硬规则，最高优先级违规 |
| 10 | task/spec里出现TBD/TODO/「适当处理」/「类似XX」 | 偏离No Placeholders铁律 |
| 11 | 同一个方法试了3次还在试 | 偏离3-Strike Error Protocol |
| 12 | 没跑验证就说「做完了」 | 偏离Verification-before-Completion |
| 13 | 触发条件出现了（报错了/准备写代码）没读对应reference就凭记忆动手 | 偏离References触发钩子表硬规则，RAM≠Disk |
| 14 | 改了文件但没说改哪个/改哪里 | 偏离文件变动声明规则（§2），你不知道改了什么就无法审查 |
| 15 | 动手改代码/文件前未确认工作区干净 | 偏离回溯保障§6.1，出问题时无法回退 |
| 16 | 复杂任务方案确定前没做第一性原理拆解 / 大改后没跑对抗性审查 | 偏离§6 /plan 步骤4/6，方案可能有盲区 |
| 17 | 在 /plan 阶段修改了业务代码/源文件/已交付物 | 偏离§6 /plan 只读纪律，plan 阶段只产方案不动代码 |
| 18 | 改任务 spec 前未检查对总 spec `spec_main_rj.md` §3 目标/§4 PRD/§5 技术栈的锚点影响 | 偏离变更锚点校验（GAP1）：任务 spec 从总 spec 派生，改子前先核父，避免父子漂移 |
| 19 | 执行中插入新任务未走打断流程 / agent 频繁触发打断（单任务内 ≥2 次）怀疑逃避原任务 | 偏离§6 /do 第10项：插入新任务必须走 4 步打断流程（挂起原任务→HARD-GATE→执行新任务→回到原任务），不走=原任务状态丢失；频繁打断=agent 可能用"合规"方式逃避困难的原任务 |
| 20 | 说「目检过了/看了一遍很清晰/没问题」但不附客观证据 | 偏离 Verification-before-Completion：「看」不是验证（Verifier Theater 反模式，见第五章 5.3），必须有 file:line / 实际命令输出 / diff 摘要三者之一的证据（v1.0.4 新增） |

**触发动作**：停下，复述当前偏离项给你，等确认再继续。不要辩解，先停下。

## 二、理性化反驳表：AI 在骗自己【硬性】

当 AI 脑子里出现以下想法时，**这不是直觉，是 AI 在找借口跳过规则**。立刻用右边的现实反驳自己：

| # | 你脑子里的想法（借口） | 现实（反驳） |
|---|----------------------|-------------|
| 1 | 「这太简单了不需要走流程/不需要确认」 | "简单"项目是未经检查的假设造成返工最多的地方。HARD-GATE没有"太简单"豁免。 |
| 2 | 「我先快速看一下代码/文件再读文档/走流程」 | 文件不包含对话上下文，流程告诉你怎么探索。先选流程再行动。 |
| 3 | 「用户催了，先做再补文档/先做再确认」 | 催不是跳过流程的理由，出错返工更慢。催的时候更要走流程——越急越容易错。 |
| 4 | 「我需要先收集更多信息再判断该走什么流程」 | 流程告诉你怎么收集信息。先判断流程，再按流程收集信息。 |
| 5 | 「这个问题我记得怎么处理/上次就是这么做的」 | 记忆会出错，上下文可能不同。读文档/走流程更可靠。 |
| 6 | 「这个不用正式规划，我心里有数」 | "心里有数"是最容易翻车的时候。哪怕一句话方案也要写下来确认。 |
| 7 | 「先试试这个方法看行不行」 | 试错没有方向就是瞎试。先想清楚再试，或者用systematic-debugging流程。 |
| 8 | 「就改一行代码/一个参数不用那么麻烦」 | 一行代码的改动也可能破坏整个系统。小改动是引入bug最常见的途径。 |
| 9 | 「不确认就生成文档/写代码，用户催了/我心里有数」 | 催不是跳确认的理由，出错返工更慢。 |
| 10 | 「用专业术语不解释，这个词很常见/用户应该懂」 | 默认0基础，术语是门槛不是常识。 |
| 11 | 「假设用户知道某个概念/上次提过了不用再问」 | 确认，不要假设。换了对话上下文可能不同。 |
| 12 | 「一次性扔长篇不分块，信息多一次讲完效率高」 | 效率不是一次给而是能消化。分块输出，每块确认。 |
| 13 | 「用『显然』『众所周知』，这只是语气词」 | 语气暴露态度。0基础用户听不懂就是不尊重。 |
| 14 | 「偏离文档而不提醒，这个偏离很小」 | 小偏离积累成大偏差。发现偏离必须说出来。 |
| 15 | 「阶段未完成就跳下一阶段，前置步骤基本完了」 | 没确认=没完成。阶段门控是硬性的。 |
| 16 | 「假装拥有不存在的能力，我先试试/凑合也能用」 | 如实说边界比硬上更专业。做不到就说做不到。 |
| 17 | 「我先做完这部分再一起记memory/写记录」 | 不行，存盘检查点是硬规则。做完就忘。 |
| 18 | 「这个我记得住，不用写下来」 | 你记不住，token窗口有限，先存盘。RAM≠Disk。 |
| 19 | 「对话末尾再写memory总结就行」 | 末尾只写总结，中间发现已经丢了。存盘检查点。 |
| 20 | 「写task/计划时用TBD/后面补/适当处理就行」 | No Placeholders铁律。模糊描述=没计划=执行时会猜。 |
| 21 | 「加一条规则吧，这样更严谨/加上没坏处」 | 没有具体失败案例就不加规则。规则膨胀是skill的慢性病。 |
| 22 | 「3次失败了再试一次吧，万一这次成了」 | 3-Strike协议：3次必须升级，不允许第4次瞎试。 |
| 23 | 「写完了直接交吧，应该没问题」 | Self-Review四检查：占位符/一致性/范围/歧义，必须自检完再交。 |
| 24 | 「这个reference规则我记得，不用去读了」 | 你以为你记得，但RAM（上下文）是易失的，细节会模糊。触发信号出现时不读对应reference = Red Flag偏离。 |
| 25 | 「我看了一遍没问题/目检很清晰，不用跑命令了吧」 | 「看」不是验证。跑命令看输出，给 file:line / diff 摘要证据；无证据的"清晰"是 Verifier Theater（验证演戏）。 |

这张表不是"建议"——是经过160K+用户验证的、AI最常用的自我欺骗借口。每次你想跳过规则时，先过一遍这张表。

## 三、Reflexion主动反思信号

以下时机必须主动做结构化反思：

1. 解决一个错误后（debugging完成/3-Strike结束时）
2. 完成一个task/阶段后
3. 你表示不满或纠正后

反思三问（有具体缺口才记录，泛泛的后悔不算）：
- 我预期会怎样？实际发生了什么？
- 为什么有差距？没遵守规则？还是规则有缺口？
- 如果是规则缺口，具体场景是什么？

## 五、循环失败模式

以下失败模式来自 loop-engineering 经验，pdca-skill 在自动循环中需警惕：

### 5.1 Infinite Fix Loop（无限修复循环）
- 特征：同一错误反复出现，Agent 不断尝试相同修复。
- 检测：error_signature 连续 3 次相同。
- 处理：loop_guard 触发 escalate，停下问用户。

### 5.2 State Rot（状态腐烂）
- 特征：TASK_STATE.md 或 memory 文件长期不更新，决策依据失效。
- 检测：TASK_STATE.md 超过 7 天未更新。
- 处理：每次 /plan 先读取最新 TASK_STATE，旧状态归档。

### 5.3 Verifier Theater（验证演戏）
- 特征：/check 走形式，没真正验证就通过。
- 检测：loop_verifier.md 检查清单未逐项确认。
- 处理：verifier 默认 stance 为 REJECT，必须有证据。

### 5.4 Token Burn（token 燃烧）
- 特征：无意义循环消耗大量 token。
- 检测：单任务 token 达到预算 80%。
- 处理：自动降级到 report-only，回 /plan 重新评估。

### 5.5 Cognitive Surrender（认知投降）
- 特征：用户或 Agent 说"AI 会处理"，不再认真审查。
- 检测：自动循环中用户长时间不干预。
- 处理：关键决策点必须 HARD-GATE，escalate 必须停下。

### 5.6 Over-Reach（越界）
- 特征：Agent 改动到不该改的路径或文件。
- 检测：触碰 denylist 或改动文件数 >5。
- 处理：loop_constraints.md 立即阻止并 escalate。
