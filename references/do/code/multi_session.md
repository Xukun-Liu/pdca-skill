# 多对话并发防撞（认领锁）

> 阶段标签：D（旧标签，以头部 PDCA 标签为准）

> 版本：v1.1 | 更新：2026-10-30

> 📖 **什么时候读这个文件**：
> - 同一 git 仓库里可能有多个对话/多个窗口在同时改
> - 用户说"我开了好几个对话在改同一个项目"
> - /do 前置检查发现 `.git/agents-locks/` 下有他人认领
> 🔴 **不要在这时候读**：
> - 单对话串行改代码（直接走 git_workflow.md 即可）

---

## 一句话规则

**改前认领，收尾释放。认领失败（退码 2）就停下问用户，不许绕过。**

## 为什么需要它

`git_workflow.md` 的改前 commit / 收尾 commit 解决的是"改坏了能退回"，属于**事后可回滚**。
但多个对话同时改同一批文件时，问题不在回滚，而在**事前不知道对方正在改**：
A 对话写了一半，B 对话收尾 commit（尤其用 `git add -u`）会把 A 的半成品一并提交，
事后也查不出是谁改的。

认领锁补的就是这一段：把"谁在改哪些文件"变成仓库内可见的事实。

## 三条命令

> ⚠️ 脚本在 **skill 包内**，不在你的业务仓库里。下面用 `{SKILL_DIR}` 占位（= 本 skill 安装目录，Windows 默认 `C:\Users\你\.trae-cn\skills\pdca-skill`），执行前换成实际路径。
> ⚠️ **必须在"要改的那个仓库目录"下执行**——脚本靠 `git rev-parse` 定位仓库，在别处跑会认领到错的仓库或直接退码 3。

```bash
# 1. /do 动手前：认领要改的文件范围（--files 尽量精确，别图省事写整个仓库）
#    --session 必填：各对话必须写不同标识，否则同名任务会被当成同一个对话而互相豁免
python "{SKILL_DIR}\scripts\session_claim.py" acquire --task {任务名} --files scripts/a.py docs/b.md --session {对话标识}

# 2. 随时查看谁在改什么（有冲突时先看这个）
python "{SKILL_DIR}\scripts\session_claim.py" status

# 3. /act 收尾：先释放认领，再 commit（--session 需与认领时一致，否则拒绝释放）
python "{SKILL_DIR}\scripts\session_claim.py" release --task {任务名} --session {对话标识}
```

## 退码语义【硬性】

| 退码 | 含义 | 必须怎么做 |
|------|------|-----------|
| `0` | 认领成功 | 正常进 /do |
| `2` | **冲突**：目标文件正被其他未过期任务占用 | **停下**，把占用方任务名+重叠文件报给用户，让用户决定换任务还是等对方。禁止自动 gc、禁止改文件名绕过 |
| `3` | 环境或参数错误（非 git 仓库 / 缺 `--session` / 路径指向仓库外） | 按提示补参数或改路径；非仓库场景降级为文件备份 |

## 冲突处理决策

认领被拒时，只有用户能决定三选一，agent 不得自行裁决：

1. **换任务**：改做不重叠的文件
2. **等对方**：占用方还在干活，等它 release
3. **确认对方已死**：用户确认那个对话已关闭 → `python "{SKILL_DIR}\scripts\session_claim.py" gc` 清过期锁后重试

## 生命周期与过期

- 默认 TTL **120 分钟**，`acquire` 时的 `--ttl` 可调
- 判断过期**只看心跳时间**，不看进程号——AI 每次执行命令都是新进程，pid 必然失效，用它判活会全部误判
- 长任务跨过 TTL：重新执行一次 `acquire`（同 task + 同 session）即刷新心跳
- 要改的文件范围变了：仍用同 task + 同 session 重跑 `acquire`，会整条覆盖旧记录，不需要先 release
- 换了任务名却改同一批文件：会被自己的旧记录挡住（退码 2），先用旧任务名 release 再认领
- `gc` 只清已过期的，不会动生效中的锁

## 与收尾 commit 的配合【硬性】

认领过的任务，收尾 commit **只能 add 认领清单里的文件**：

```bash
git add scripts/a.py docs/b.md      # ✅ 只加自己认领的
git add -u                          # ❌ 单会话可用，多会话禁止（会带走别人的半成品）
git add .                           # ❌ 永远禁止
```

## 边界（别指望它解决什么）

- ❌ **不是实时协同**：两人同时改同一行仍会产生 git 冲突，需要人工合并
- ❌ **依赖自觉**：某个对话跳过 acquire 直接改，锁不会生效——所以它被写成 /do 的硬前置，而不是一句提醒
- ❌ **不替代备份**：锁防撞车，不防硬盘损坏；远程备份另见 git_workflow.md

## 实现说明

- 锁记录存放于 `<git-common-dir>/agents-locks/*.claim`，在 `.git` 内部，**不会被提交、不污染工作区**
- 跨进程原子性由 `msvcrt`(Windows) / `fcntl`(Linux) 文件锁保证，与 `memory_shadow_write.py` 中的 `_CrossProcessLock` 同源
- 路径重叠判定覆盖四种情况：整仓库（`.` 或空）、完全相同、父子目录、通配符（如 `docs/*.md`）
- 认领身份 = 任务名 + `--session`，两点都相同才视为"同一个任务"
- 认领文件名 = 任务名 slug + 8 位哈希，避免 `B3 记忆` 与 `B3_记忆` 这类 slug 碰撞互相覆盖
- 认领记录原子写入（临时文件 + `os.replace`），进程中断不会留下坏 JSON；真坏了会告警，不会静默跳过
