管理学的答案

PDCA 戴明环——质量管理方法论 × AI 协作

这不是拍脑袋想出来的流程，而是被全球制造业、服务业、软件开发验证了70年的管理科学。

PDCA 是什么？

PDCA（Plan-Do-Check-Act）循环，又称戴明环，由质量管理大师 W·爱德华兹·戴明在1950年代提出。它最初用于日本制造业的质量改进（丰田生产方式的核心），后来被 ISO 9001 国际标准采纳，成为全球公认的持续改进方法论。

核心思想：任何工作都可以拆成四步循环——先计划（Plan）、再执行（Do）、然后检查（Check）、最后处理改进（Act）。完成一轮后，把经验教训带入下一轮，形成螺旋上升的持续改进。

为什么适用于 AI 协作？ AI 助手最大的问题不是"不聪明"，而是"没章法"——没计划就动手、做完了不检查、做错了不复盘。PDCA 正好解决了这4个问题。riji-skill 把 PDCA 做成统一调度中枢：你只需记 /plan /do /check /act 四个词，所有能力——记忆系统、副 agent 调度、文档三件套、/loop 循环、learn 自进化、handoff_tidy、触发钩子、第一性原理拆解、对抗性审查、用户数据外置、Bootstrap 初始化、Git 回溯保障、SUMMARY 根索引、Red Flags、安全处理、手绘呈现、agent-find——都在这四步里自动归位。

丰田用 PDCA 把汽车缺陷率降到百万分之一，ISO 用 PDCA 管理全球数百万企业的质量体系。

riji-skill 做的事很简单：把 PDCA 从"管理学课本"搬进"AI 助手的日常习惯"。你说 /plan，AI 就进入"计划模式"——先想清楚再动手；你说 /do，它才动手干；你说 /check，它对照标准逐条验收；你说 /act，它把经验教训存进记忆，下次用得上。

先讲痛点

你请的 AI 助手，为什么总让人不放心？

不是 AI 不够聪明，而是它缺少一套"协作规矩"。以下4个问题，几乎所有 AI 助手用户都遇到过：

🤦

没问清就动手，做偏了返工

你说"帮我优化一下"，AI 直接改了一大堆代码，结果改的方向和你想的完全不一样。来回返工，浪费时间。

HARD-GATE 硬规则——AI 必须先呈现方案，等你确认才动手。哪怕改一个参数，也要先说清楚。
💥

改着改着改崩了，找不回上一版

AI 改代码没做备份，改着改着功能全崩了，想回退也回不去。就像装修没留图纸，砸了墙发现里面是承重墙。

回溯保障铁律——改代码前必须确保工作区已 commit，改错了一键回退。
🤔

聊着聊着它"忘了"之前定好的事

上下文窗口是有限的，对话一长 AI 就"失忆"——上次确认过的方案、踩过的坑，全忘了，又要重新说一遍。

Memory First 铁律——重要信息自动写入文件（"存硬盘"），每次启动自动读取。就像个人笔记本，越记越厚，下次直接用——不只是"不失忆"，更是"积累复利"。
😤

出错了一直瞎试，试到崩

AI 遇到报错就反复试同一个方法，试了3次还不行继续试，浪费 token 不说，还把代码改得更乱。

3-Strike 协议——同一方法试3次失败，立即停下，升级给你决策。不允许第4次瞎试。

Loop Engineering——让 AI 在约束下自动循环迭代

管理学有一句话："你考核什么，就得到什么。" Loop Engineering 就是 AI 的考核与约束系统——让它在安全边界内自动循环，碰到问题自动停下。

🔁 /loop 触发词——自动循环模式

定位：/loop 不是第5环，而是 /do+/check 的"自动循环模式"。用户说 /loop 后，AI 在约束下自动推进 /do→/check→/do→/check 循环，直到完成或触发熔断。

3 个前置条件（必须全满足）：

  • ▸ /plan 已得到用户明确确认
  • ▸ 跑 python scripts/loop_admission.py . 退码=0 且 level≥L2
  • ▸ 必须是 git 仓库（铁律6 回溯保障）

四级任务等级

等级 名称 定义 /loop 行为
L0拒绝不具备 loop 条件不准入
L1Report-only只分析/出报告，不改代码拒绝（全程人工决策）
L2Assisted/plan 确认后，AI 在约束下自动执行小改动可选半自动
L3Unattended完全无人值守自动执行可选全自动

4 类熔断条件（触发即停回人工）

  • ▸ 同一错误连续 3 次（stagnation 停滞）
  • ▸ 任意失败连续 5 次（no_progress 无进展）
  • ▸ 单次任务总迭代 ≥10 次
  • ▸ 触碰 denylist 路径或改动文件数 >5

🏢 类比：自动巡航——/loop 是自动巡航开关，但司机（用户）随时可踩刹车

Loop Engineering 的设计哲学来自控制论（Cybernetics）：任何自动系统都需要反馈回路 + 安全边界。riji-skill 把这一思想落地为：loop_admission（准入审计 22项信号）→ loop_guard（运行时熔断）→ loop_audit（事后审计），形成完整的自动化治理闭环。

💾 RAM vs 硬盘——一个关键类比

AI 的上下文窗口 = 电脑的 RAM（内存）——易失、有限、速度快。

文件系统 = 电脑的硬盘——持久、无限、跨对话保留。

任何重要信息必须写入文件。只在上下文里记着 = 没存。

riji-skill 的 Memory First 原则就是：启动先读硬盘（恢复记忆），结束必写硬盘（保存记忆），中间关键节点存盘（防止丢失）。

📦 用户数据外置：记忆、文档、输出等用户数据放在 ~/.riji-skill/data/，与框架文件物理分离。升级时解压覆盖框架文件，用户数据 0 丢失——再也不用担心升级覆盖丢数据。三级优先级路径解析（环境变量 > 配置文件 > 默认值），老用户首次启动自动迁移。
